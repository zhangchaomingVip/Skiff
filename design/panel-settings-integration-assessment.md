# 主页面改造评估：统一设置入口

评估日期：2026-10-17。对象：`design/panel-settings-mockup.html`，对照当前仓库实现。

## 结论

**建议采纳统一设置入口和界面减负方向；当前原型需修订后才能作为完整主页面的实施规格。**

这次改造的主要价值是把全局偏好集中管理，让聊天区更专注。主要风险不是 CSS 工作量，而是原型简化了现有的模型线路、推理等级及多会话状态。如果逐块替换现有页面，会发生功能回退。

建议第一期只完成设置入口整合和视觉调整，保留现有聊天、模型选择、线路授权和会话状态逻辑。原型中的通用设置、语言、断连等新能力另行定义行为。

## 值得保留的设计

- 左下角固定入口适合承载全局设置；主题、模型配置、快捷键帮助聚合后，可以减少顶栏按钮。
- 输入区附近放置模型与推理控件，操作与下一次发送的关系清晰，符合现有 Composer 的结构。
- 设置采用左侧分类、右侧内容，较适合后续扩展；外观菜单与设置页共享选择状态的方向正确。
- 侧栏、聊天区和空态的层级较清楚，浅深色变量也便于映射到现有设计令牌。

## 优先解决的问题

### P1：模型滑杆丢失线路选择语义

原型第 725–738 行仅列固定家族与型号，第 785 行把来源固定为 `opencsg`；第 789–805 行将型号映射成滑杆档位。当前项目选择的是具体 Offer（线路 × 模型），同一型号可能出现在多个中转和扣费账户下。`ModelPicker.tsx:23` 已展示来源、账户和价格，`features/007-route-selection-trust/DESIGN.md:13` 定义了实际选择单位。

因此，“型号相同”不等于“选择相同”。型号也不是天然有序的强弱等级，滑杆只展示两端名称，难以比较中间项和多个线路。

**建议：**保留可搜索、按家族和供应商分组的列表。入口可以更简洁，但选项应显示型号、线路、扣费账户和价格。家族是筛选维度，不应另建一套独立选中状态。默认选择使用现有配置与 Offer 解析，不使用数组第一个型号。

### P1：把推理能力误当成推理等级

原型第 743 行认为 `reasoning` 是布尔值，因此只提供开/关。该布尔字段表示线路是否具备能力；当前会话仍通过 `get_available_thinking_levels` 获取等级，通过 `set_thinking_level` 设置（`usePiSession.ts:542`、`:553`）。现有 `ReasoningChip.tsx` 按实际等级渲染。

**建议：**从运行时读取可用等级；只有实际支持两档时才显示开关。无能力时可显示不可用及简短原因；切换模型后重新读取能力和当前值，不能沿用原型全局 `reasoningOn`。

### P1：快捷键冲突，弹窗不能隔离后台操作

原型将 `Ctrl+K` 设为切换 Kimi（第 935 行附近），现有 `Composer.tsx` 已将其用于聚焦输入框，迁移时会发生行为冲突。原型显示 `Ctrl+N`，但没有对应处理；现有 `App.tsx:181` 已实现新聊天，并检查模态对话框。

**浏览器已复现：**打开设置后焦点仍在背后的家族按钮；此时按 `Alt+↓`，后台模型从 `deepseek-v4.1-flash` 变为 `deepseek-v4.1`，设置面板仍打开。

**建议：**保留 `Ctrl+K` 聚焦及 `Ctrl+N` 新聊天；第一期不增加固定家族快捷键。统一处理快捷键作用域、输入法组合输入、模态窗口和运行中禁用状态。复用现有 `Dialog`、`Popover`，设置页增加明确关闭按钮。原型中的可点击 div、滑杆和无名称开关还需要补齐键盘及无障碍语义。

### P1：最小窗口下模型弹层被裁切

应用配置允许最小 `600×400`（`src-tauri/tauri.conf.json`）。原型侧栏固定 280px，弹层依赖绝对定位，没有边界翻转或断点规则。

**浏览器已复现：**在 `600×400` 下打开模型弹层，其边界为 x=424.44 至 704.44，右侧超出窗口约 104px；输入区占高约 227.5px。页面 `overflow:hidden` 进一步限制查看溢出内容。

**建议：**沿用现有窄窗侧栏抽屉、可调列宽和 `ui.tsx` 的弹层边界计算。不要固定复制 280px 侧栏。设置在窄窗可改为抽屉或单列分类选择，需验证 600×400 和 1100×750。

### P1：完整主页面缺少现有能力的迁移位置

原型没有覆盖航行台、后台会话入口、附件、联网搜索、插话/排队、停止运行、归档恢复、系统提示词、诊断日志等。这里不是认定这些能力已经被删除，而是指出：**原型尚不足以定义完整替换方案。**

特别是用量菜单中的“本期 0 / 128k tok”把累计用量与上下文窗口容量混在一起，不能替代现有航行台实时指标。

**建议：**按下表补齐映射；实时运行和上下文状态继续留在聊天区。无边框 Tauri 窗口仍需要现有 `TitleBar` 的拖拽、最小化、最大化和关闭能力。

| 现有能力 | 建议新位置或处理方式 |
| --- | --- |
| 模型目录首页、最近会话 | 保留 `LauncherView`；区分“主页”和“新聊天”，避免原型中主页入口成为空操作 |
| 模型、线路、账户、价格 | 输入区模型选择器；继续复用 `ModelMenu` / `ModelPicker` |
| 推理、联网、附件、停止、队列 | 输入区；保留 `Composer` 的行为与状态 |
| 航行台、工具航迹、上下文 | 聊天区侧栏或折叠摘要；不全部收进设置 |
| 后台运行会话、分享 | 顶栏，保留运行状态和当前会话范围 |
| 主题 | 统一设置 → 外观；可保留菜单快捷入口，调用现有主题存储 |
| 供应商、线路、模型能力 | 统一设置 → 模型与提供商，复用原有配置表单 |
| 归档恢复与删除 | 统一设置 → 归档会话，保留现有入口能力 |
| 系统提示词 | 保留会话作用域，可放聊天更多菜单；避免误表达为全局偏好 |
| 诊断日志、连接信息 | 更多菜单或设置 → 诊断；显示当前会话与后台会话范围 |

### P2：切家族两次确认过重，且文案自相矛盾

第 871 行说明保留历史、下一条消息开始使用新家族；第 877 行又说“立即生效且不可撤销”，随后允许切回。当前 `setModel` 本身也不是删除历史的操作，且在生成、停止或排队阶段有保护（`usePiSession.ts:530`）。

**建议：**空闲时允许明确选择具体模型和线路，必要时一次确认并说明后续请求的影响；保留已有跨扣费账户故障切换授权流程。是否需要确认，应由实际后果决定，不能仅按是否跨家族决定。不要把两次确认当作默认安全要求。

### P2：原型部分状态反馈不能作为真实产品行为

- 空输入点击发送也调用 `setSession(true)`（第 907 行附近）。浏览器已复现欢迎页消失、演示消息出现；随后切家族还提示“已产生 0 条消息”。正式版应保留现有空消息校验，发送被接受后才切换状态。
- 设置通过替换 `innerHTML` 重建内容，开关仅切换 CSS class（第 1145 行起）；切换页签会丢失这类修改。应明确自动保存、失败反馈和持久化方式。
- 自定义 CLI 路径、语言、字体大小、供应商“管理”等仅有外观或缺少完整行为；默认模型选项与聊天模型表不一致。第一期仅展示已接通的设置。
- 左下角以模型品牌命名，却实际打开全局菜单；头像 tooltip 说可切家族，点击只提示到聊天区操作。建议入口命名“设置”，附连接摘要；不要把局部头像设计成另一条死路。
- “断开 pi 连接”只改状态文案，而设置“关于”仍硬编码已连接。当前项目存在多个会话实例，必须先定义断开当前会话还是全部会话、运行中如何处理，以及如何重连。

### P2：小字号文字对比度不足

按原型颜色计算：`#9b9b9b` 对白色约 2.78:1；`#6e6e6e` 对深色背景约 3.16–3.45:1；`#4f6ef7` 对浅色选中背景 `#eef1fe` 约 3.80:1。必要说明和导航文字未达到普通文字 4.5:1。

建议沿用项目设计令牌，调整说明文字、选中态文字和焦点样式，并支持减少动效偏好。单独修正颜色不足以解决前述状态与交互问题。

## 实施范围与成本

以下是熟悉本仓库的一名开发者的初步工作量，包含基础回归，不是交付承诺；未包含新增后端设置协议和完整国际化。

| 阶段 | 内容 | 估算 |
| --- | --- | --- |
| 第一期：入口与视觉整合 | 统一设置菜单和容器、迁移主题与配置入口、精简顶栏、保留原有业务逻辑，验证窄窗和焦点 | 2–4 人日 |
| 第二期：聊天控件调整 | 如确有需要，调整模型/推理呈现，补齐运行状态、快捷键作用域及会话切换回归 | 2–4 人日 |
| 新增设置能力 | CLI 路径、自动恢复偏好、字体、语言、断连生命周期 | 需先定义存储、作用范围和后端接口，再估算 |

建议增加 `SettingsMenu` / `SettingsDialog` 负责导航；将 `FamiliesSettings` 的内容与它自己的 `Dialog` 容器拆分后嵌入，避免模态窗口套模态窗口。继续使用 `useModelFamilies`、`usePiSessions`、`theme.ts` 和 `ui.tsx`，不复制原型的全局变量、字符串模板和 DOM 事件管理。

## 验证依据与验收要求

本次已完成：原型及现有代码对照、浏览器打开与模型弹层操作、空发送流程、家族确认、设置焦点及后台快捷键、600×400 弹层几何测量、颜色对比度计算。未修改业务代码，未运行构建或协议测试；未连接真实 pi 或供应商，未实测屏幕阅读器、深色渲染和 200% 缩放。

实施后至少验证：

1. 同型号不同线路可区分，选中身份与实际 RPC、历史线路快照一致；配置与归档入口可达。
2. 切换模型后推理等级正确刷新；生成、停止、排队和会话切换期间不产生错误状态。
3. 设置可用键盘打开、操作、关闭并恢复焦点；模态窗口内不会切换后台模型。
4. 600×400、1100×750 以及缩放场景下发送、停止、关闭和模型选项不被裁切。
5. 附件、联网、流式回复、工具展示、插话、分享、草稿恢复和后台会话能力不回退。
6. 按变更运行 `npm run build`、`npm test`、`npm run check:ui`、`npm run test:styles`；涉及 Rust 再运行相应 native 检查。

## 对既有静态评审的补充

`panel-settings-review.md` 对对比度、假快捷键、焦点和占位设置的意见基本成立，但有三点需要修正：

- 不能把两次切家族确认直接判定为优点，应先核对操作是否可逆及真实业务后果。
- 子菜单越出侧栏本身不是缺陷，浮层可以覆盖主区；应关注视口裁切、遮挡及键盘可达。本次实际发现的是模型弹层越出窗口。
- 原评审明确未做浏览器实测，部分硬门 PASS 不应被视为验证通过。本次已补充上述具体复现；完整功能验收仍需在正式实现中进行。

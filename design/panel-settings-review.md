# 设计评审 · panel-settings-mockup.html

**评审人角色**：星衡（UI/UX 设计系统总监）
**评审类型**：可用性 + 视觉质量静态走查
**路线判断**：product / 桌面端 AI 聊天外壳（Tauri v2）/ audit 模式
**核心任务**：在桌面端聊天界面中切换模型家族/模型/推理、管理统一设置、分享会话。
**证据范围**：完整 HTML/CSS/JS 源码走查；关键文字对比度手算；交互流程依据 JS 推断。**未做浏览器实测**，故交互/响应式/无障碍项标注为「代码推断，未实测」。

---

## 1. 结论（Verdict）
**`NOT PASS`（需修复后复测）**
- 适用硬门关失败：文字对比度（`--text-tertiary` 在说明/副标签文字上低于 WCAG AA 4.5:1）。
- 综合判断：界面整体完成度高、设计令牌统一、空态与反馈良好；但存在 1 项硬门失败 + 若干 P1 可用性问题，需修复并复测方可达发布门槛（≥70 分档）。
- 未给数字评分：用户未要求打分；且静态稿无法对「交互/响应式/无障碍」取得 4–5 分证据，按评审契约不臆测通过。

## 2. 硬门（Always-On Hard Gates）
| 硬门 | 结果 | 证据 |
| --- | --- | --- |
| 核心任务可完成 | PASS | 发送消息、Ctrl D/K/G 切家族、Alt↑↓ 切模型、设置弹窗均可走通 |
| 无遮挡/裁剪/溢出隐藏关键内容 | PASS（P2 备注） | 子菜单溢出 280px 侧栏（仅视觉越界，未遮关键） |
| 文字/控件边界对比度达标 | **FAIL** | 见下「对比度」 |
| 键盘焦点 / 触控目标尺寸 | PASS* | 桌面鼠标场景；缺 `:focus-visible` 与弹窗焦点陷阱（P1） |
| 核心流程具备必要状态 | PASS | 空态(hero)、分享失败兜底、切家族两步确认 |
| 高风险操作标明对象与后果 | PASS | 断连用原生 confirm 写明后果；切家族两步弹窗写明 from→to |
| Logo/资产权属 | PASS | 提供商 SVG 取自 Magpie 图标集（MIT，代码注释已标注） |
| 无虚假/占位声称 | PASS* | `Ctrl N` 标注但未实现；`gpt-4o` 不在 FAMILIES（P1） |

### 对比度（实测）
- 浅色 `--text-tertiary` `#9b9b9b` 白底：≈ **2.79:1**（12px 说明文字需 4.5:1）→ 失败。
- 深色 `--text-tertiary` `#6e6e6e` 于 `#191919/#212121`：≈ **3.1–3.5:1** → 失败。
- 受影响：**`.setting-row .desc`(12px)、`.main-header .sub`、`.menu-hint`、`.st-hint`、`.composer-hint`、项目计数、kbd 标签**——其中 `.desc` 是解释性必要文字，必须达标。
- 边缘项：浅色 `--accent` `#4f6ef7` 作 13.5px 加粗文字 ≈ 4.31:1，略低于 4.5（活跃导航/链接），建议同步收紧。

## 3. 关键发现（P0 / P1 / P2）
格式：`问题 → 影响 → 违反标准/证据 → 修改 → 复测`

### P0（硬门失败 / 发布阻断）
**F-01 三级文字对比度不足**
- 问题：`--text-tertiary` 用于 11–12px 说明与副标签，浅色 2.79:1 / 深色 3.1–3.5:1，低于 AA 4.5:1。
- 影响：设置说明、副标题、提示在小字号下难以阅读，老年/低视力用户受阻。
- 标准：WCAG 1.4.3（正常文字 ≥4.5:1）。
- 修改：所有承载信息的 11–12px 文字改用 `--text-secondary`（`#6b6b6b` 浅色 ≈5.33:1 / `#a0a0a0` 深色 ≈6.7:1）；将 `--text-tertiary` 仅保留给非文字 UI（分隔线、kbd 背景）。或把 tertiary 直接提亮到 `#767676`(浅)/`#9a9a9a`(深) 但仍需区分于 secondary——**推荐前者（语义分层更清晰）**。
- 复测：重算对比度；检查 `.desc/.sub/.hint` 在两种主题下的可读性。

### P1（重大可用性 / 系统缺陷）
**F-02 模型切换入口割裂、可发现性差**
- 问题：侧栏底部「模型入口」显示 `DeepSeek · deepseek-v4.1-flash · 已连接`，点击头像仅 `toast`「请在对话区切换」；真正的切家族/模型/推理控件藏在 composer 状态条的三个低调 chip 里。同时侧栏弹菜单的「模型与提供商」与对话区 chip 是两套并行的模型设置面。
- 影响：用户第一直觉在侧栏入口改模型，结果不可操作；低强调 chip 易被忽略，导致核心能力（切模型）难以被发现。
- 标准：交互优先——核心动作应置于最显眼处；信息架构与用户既有心智一致。
- 修改：二选一——(a) 让侧栏入口真正可操作（点击直接展开模型选择）；(b) 移除侧栏入口的「状态+点不动」误导，把模型切换提升为对话区主级控件并加可见标签/图标。建议统一为单一模型切换入口。
- 复测：可用性走查——不提示下找到并切换家族/模型/推理；检查两种方案下误触率。

**F-03 标注 `Ctrl N` 但未绑定热键（虚假快捷键）**
- 问题：侧栏「新聊天」与设置「快捷键」页均标注 `Ctrl N`，但 `keydown` 仅处理 `d/k/g` 与 `Ctrl+,`，无 `Ctrl N` 监听；在网页稿中按 `Ctrl N` 会触发浏览器新建窗口。
- 影响：用户依提示操作无效，信任受损；不一致声称属内容真实性问题。
- 标准：内容真实性 / 快捷键需可用或有明确说明。
- 修改：在 keydown 中补充 `Ctrl N → 新聊天`（并 `preventDefault`）；或在 UI 中改标为实际行为。
- 复测：按 `Ctrl N` 触发新聊天且不弹浏览器窗口。

**F-04 子菜单（外观/语言）仅 hover 展开**
- 问题：`.menu-item.has-sub:hover .submenu` 才显示，无键盘聚焦/点击打开逻辑。
- 影响：纯键盘或触摸用户无法进入主题/语言选项。
- 标准：交互优先——hover 不能是唯一可达方式；键盘/触摸需替代路径。
- 修改：子项可点击/可聚焦展开（点击切换 `.expanded` + 焦点进入），`Esc`/失焦收起；或改为行内可展开区块。
- 复测：仅用键盘 Tab+Enter 打开并选择主题/语言。

**F-05 缺 `:focus-visible` 与弹窗焦点陷阱**
- 问题：全局未定义焦点环；设置/确认/分享弹窗打开后焦点未移入、未陷阱（Tab 可逃出遮罩）。
- 影响：键盘用户定位困难，弹窗可达性不达标。
- 标准：响应式与无障碍——可见焦点 + 对话框焦点管理。
- 修改：为按钮/菜单项/`textarea`/select 增加 `:focus-visible` 描边（用 `--accent`）；弹窗 `show` 时聚焦首个可聚焦元素并陷阱循环，`Esc` 关闭。
- 复测：键盘全程操作各弹窗，焦点可见且不出界。

**F-06 设置数据不一致 / 死路**
- 问题：设置「模型与提供商」页「默认模型」列出 `gpt-4o`（不在 FAMILIES）；「OpenAI 兼容提供商 已配置 3 个」未经验证；「pi CLI 路径」选「自定义…」后无输入框出现。
- 影响：呈现与真实数据不符，且存在无意义选项。
- 修改：默认模型选项对齐 FAMILIES；自定义路径选中后展开输入框；无法核实的数据标注为占位。
- 复测：逐项核对选项与运行时数据一致。

### P2（精炼项，不阻断核心结果）
- **F-07 图标语法不一致**：项目行与 hero 用 emoji（📁/✦），其余为 SVG 图标。→ 用 SVG 文件夹/星标图标替换 emoji，统一图标族。
- **F-08 确认范式不一致**：切家族用自定义两步弹窗，断连用原生 `confirm()`。→ 统一为同一种确认组件。
- **F-09 模型滑条 fill 起点(0) 与 dot/knob 区间(6–94%) 轻微错位**。→ fill 也映射到 6–94% 坐标系。
- **F-10 子菜单溢出 280px 侧栏**（`left:calc(100%+6px)` + 160px 宽），浮于主区。→ 约束在侧栏内或改为上/下展开。
- **F-11 缺 `prefers-reduced-motion`**：所有 transition 在减弱动效偏好下仍生效。→ 加媒体查询关闭非必要动效。
- **F-12 语义标签**：「发送」是 `div.pill` 非 `<button>`；`themeValue` 文本尾随空格。→ 改 `<button>`、清理尾空格。
- **F-13 弹窗上开越界风险**：composer 弹层 `bottom:calc(100%+8px)` 在极矮窗口可能顶出视口。→ 加边界翻转。

---

## 4. 修订顺序（最小修复序列）
1. **F-01 对比度**（硬门）→ 改 `--text-tertiary` 用途 + `.desc/.sub/.hint` 用 secondary。
2. **F-03 `Ctrl N` 绑定** + **F-06 数据对齐**（内容真实性）。
3. **F-02 统一模型切换入口**（最大可用性增益）。
4. **F-04 / F-05 键盘与焦点**（无障碍）。
5. **F-07~F-13** 视觉与一致性精炼。

---

## 5. 已验证的优点（保留）
- 设计令牌统一（CSS 变量 + 浅/深双主题），间距尺度清晰。
- 空态 hero 明确；操作后 toast 反馈到位。
- 切家族「两步确认」对高后果操作做了 consent + 可回退说明（良好）。
- 模型操作键盘快捷键（Ctrl D/K/G、Alt↑↓、Alt←→）提升效率。
- 非色彩语义线索齐全（推理「不可用」文字 + 禁用态）。
- 提供商图标取自真实 MIT 图标集并标注来源。

## 6. 验证范围与限制
- **已执行**：完整源码走查；对比度手算；状态/流程依据 JS 推断。
- **未执行（标注）**：真实浏览器渲染、像素级布局、触控、屏幕阅读器、200% 缩放、窄窗响应式、动效实测。
- 静态稿不对「交互/响应式/无障碍」声称 4–5 分；以上 P1 项需落地后在真实桌面环境复测。

# 032 · 航行台重构：数据看板、领航员与工具航迹

状态：已实施（2026-11 多次迭代落地，本文档为补录）。替代原航行台系列（010 航行台体验、015 仪表盘视觉收敛）的展示层设计；009 工具瀑布与 011 上下文统计口径的约定仍然有效，本文描述其上的现行实现。

## 背景

原航行台以速度统计、钓鱼等待态和仪表盘指针为核心（010/015）。重构后航行台改为「数据看板 + 领航员」的舞台式布局：右侧轨道（`VoyageRail`）承载一个环绕场景，左半是四张指标卡（`VoyageBento`），右半是领航员甲板（`Companion`），下方是工具航迹（`ToolCapsule` + `ToolLog`）。钓鱼等待态已移除，等待与运行状态改由领航员姿态表达。

## 布局结构

```
VoyageRail（aside.voyage-rail，状态类 voyage-{pressure} voyage-{activity}）
├── 头部：「Skiff 航行台」标题 + 窄屏收起按钮
├── 环绕舞台（voyage-stage-orbit）
│   ├── VoyageBento：航行数据看板（4 张天气卡）
│   └── 领航员甲板（Companion）
└── 工具航迹区（有 timeline 或工具时渲染）
    ├── ToolCapsule：仅运行中的工具
    └── ToolLog：「航海日志 · N 项已入日志（M 次失败）」折叠列表
```

## 数据看板（VoyageBento）

四张 `WeatherCard` 统一结构：图标 + 标签、主读数（大字）、迷你可视化、两行摘要、`明细` 触发按钮打开 Popover 台账（`Ledger`）。整卡可点区域仅明细按钮，卡片本身不是控件。

| 卡片 | 主读数 | 迷你可视化 | 摘要 | 明细要点 |
| --- | --- | --- | --- | --- |
| 推理速率 | tok/s（流式中显示实时速度，完成后显示平均） | 弧形仪表 + 指针 | 首字延迟 · 速率峰值 | 模型用时/工具用时拆分、本轮与会话速度、首字均值（按已记录轮次） |
| Token 用量 | 新增消耗 = 非缓存输入（含写入）+ 完整输出（含思考） | 历史各轮非缓存输入趋势线（单轮显光点，缺失断开） | 输出 · 新增输入 / 总吞吐（含缓存） | 轮数/步数、上报进度、工具成败计数、较上轮输入增量、模型/工具时间条、会话累计 |
| 上下文窗口 | 占用百分比 | 容量条 | 当前占用 · 窗口上限 | 上下文构成估算（对话文本/工具结果/系统与工具开销）、数据来源；超过 80% 警告色并建议开新话题 |
| 缓存 | 命中率百分比，或「写入准备」态 | 天气环（命中进度/准备虚线） | 缓存创建 · 缓存读取 | 本轮缓存账单（读取/创建/命中/预估费用/节省）、会话累计命中率与节省 |

约定：

- **口径**：上下文占比、累计消耗、最近请求输入分离（沿用 011）；看板中的「非缓存输入」「总吞吐」都不是去重内容量或费用，明细台账中明确标注。数据来源分 pi 上下文快照 / 最近模型请求 / 本地估算，在明细中说明。
- **暂存读数**：模型尚未上报当前轮数据时，卡片暂显最近读数并以 `暂显最近读数` 标记（`display.retained`），Popover 内同时展示本轮已上报数据。
- **估算标记**：生成中或缺 usage 的读数为估算，明细注明「当前为估算」/「已按用量校准」。
- **状态色**：上下文 >80% 警告；缓存按 命中 >70% 显示节省色、仅写入显示准备态、无命中显示安静态。

## 领航员（Companion）

航行状态的情感化化身，五档姿态：

- **idle** 空闲、**happy** 顺利完成、**eat** 高速消化（高命中率/高速度）、**sleep** 停滞等待（含 `z z` 气泡）、**angry** 工具失败或错误后的跺脚。
- 姿态由 `companionPose` 依据 metrics 推导：流式状态、运行阶段、活动度、上下文占比、活动工具数、最近工具失败、轮次命中率。

交互：

- 单击：戳一下（tap 帧 640ms + 弹性挤压动画），姿态不变。
- 双击：捏扁（squash 动画 + angry 姿态 3 秒），提示「领航员被捏扁了，正在跺脚」；真实状态变化会提前接管姿态。
- 右键：更换领航员图片（webp/gif/png ≤1MB，本地存储）；自定义后可一键恢复默认。
- 减少动态效果：静止帧（idle.png），关闭全部动画；图片缺失时逐级回退（自定义 → idle.webp → idle.png → 幽灵占位）。

## 工具航迹

- **ToolCapsule**：只有进行中的工具常驻舞台（倒序，`aria-live` 播报执行中工具）；完成的工具一律收进日志，不占舞台。
- **ToolLog**：`<details>` 折叠，标题含总数与失败数（失败为 0 时隐藏括号）。
- 工具行：状态图标（完成 ✓ / 失败与超时 ✕ / 运行中按工具类型图标）、工具名、目标摘要、非完成态状态标签、耗时（仅长工具显示）、结果摘要（title 带完整内容）。失败、超时、中止、缺少结果均有明确状态。

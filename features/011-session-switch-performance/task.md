# 011 · 会话快速切换与加载性能

状态：首批实现完成，自动行为回归通过。创建日期：2026-10-10。极端历史、大侧栏性能及真实 Tauri/WebView2 验证边界见 verification.md。

## 背景与目标

用户在左侧栏选择会话 A，在 A 加载完成前立即选择 B，感受到明显卡顿。需要区分三种现象：B 的按钮被禁用、前端主线程无法及时响应、B 的加载等待旧会话进程退出。三者分别记录，不能把加载耗时直接解释为渲染阻塞。

本 feature 的首批交付是：真实侧栏点击回归、完整会话状态归属隔离、允许在加载期间继续切换。用户选中 B 后应及时看到 B 的选中状态和加载反馈；A 的迟到结果不能覆盖 B；加载失败仍可查看错误并重试。

## 首批行为契约

- 加载期间允许继续选择其他已有会话；同项目和跨项目均适用，最后一次有效选择决定当前目标。
- 选中 ID、标题、项目和加载反馈及时切换到目标会话；新会话子树不接收属于旧会话的消息、模型、错误或运行状态。
- 会话快照同时记录所属会话和加载批次。A→B→A、同会话重连及工作目录变化都能使旧批次失效，不能只比较会话 ID。
- 加载批次覆盖 loading、ready、error 的完整生命周期。不能仅用 `loadedId === activeId` 控制状态可见性，避免隐藏初始化错误和重试入口。
- 消息、模型、错误、pending、连接状态、计时、诊断日志和会话文件等派生数据按同一归属规则处理；历史快照、线路事件和会话索引不得写入错误会话。
- 生成中和发送、回退消息、修改模型等进行中的操作继续保留对应限制。只解除“加载导致的导航禁用”，不因切换功能终止正在执行的任务。
- 统一检查侧栏、项目选择、右键菜单及 Launcher 已有会话入口，避免同一状态下出现可绕过限制的入口。
- 保留现有串行退出与启动机制。迟到进程仍需被清理，过期批次不提交结果或触发后续初始化工作。
- 加载期间显示明确加载反馈；空历史在加载成功后显示空会话；失败显示当前目标的错误及重试操作。

## 回归矩阵

| 场景 | 必须验证 |
| --- | --- |
| 已加载长会话 A→B | B 的首次渲染不挂载 A 的消息；加载反馈及时 |
| A 启动中→B | 真实侧栏可选 B；释放 A 的启动后迟到进程被清理 |
| A 恢复或历史请求挂起→B | 不等待旧 RPC 的 35 秒超时；B 可恢复 |
| A 的成功、错误、退出事件迟到 | 不改变 B 的内容、错误、连接状态和索引 |
| A→B→C、A→B→A | 最新批次生效；同一 ID 的旧批次仍失效 |
| 同会话重连、同 ID 工作目录变化 | 新批次独立，旧响应不能覆盖当前模型或错误 |
| B 初始化失败→重试 / 选择 C | 错误和重试入口可见；无永久 loading |
| 重复选择当前目标 | 不重复启动、恢复或读取历史 |
| 生成中或命令执行中尝试切换 | 各导航入口遵守限制；不意外停止 pi 或重复发送 |
| 卸载与连续切换结束 | 所有已释放的旧批次 pending、计时器、监听器和进程清理；挂起启动单独记录，不能假报已清理 |
| 元数据恢复与持久化 | sessionFile、模型选择、RouteSnapshot、RouteEvent、计时写入正确会话；重载后仍正确 |

## 性能测量约定

- 消息规模分别为 100、1,000、10,000 条；纯文本、大代码块、工具结果、图片分别建立固定 fixture，记录总字节数、代码行数及图片尺寸，避免只比较消息条数。
- 侧栏会话规模单独测量，避免与消息历史规模同时增长而无法归因。至少覆盖 30、300、3,000 个会话，以及项目折叠与展开。
- 性能对比使用 production 构建的隔离 mock 入口；现有 dev 预览可用于行为验证，但不能冒充 production 性能数据。真实 Tauri/WebView2 的启动退出另行测量。
- 每个对比场景预热后至少采集 30 次，冷启动单列；固定延迟注入、视口及 CPU 限速设置。开启 Profiler 的分析采集与关闭分析工具的用户响应测量分开记录。
- 初始交互目标为点击到目标高亮和加载反馈 P95 ≤100 ms；超过 50 ms 的主线程任务列出调用栈。目标需注明适用设备及 fixture，不能当作已经达到的结果。
- 历史加载完成时间与交互反馈独立统计。报告必须能区分旧进程等待、RPC 等待、解析、React 渲染及布局成本。

## 按测量结果进入的后续优化

这些是候选任务，不与首批修复捆绑。每项进入实施前在 `verification.md` 写明触发证据、预期收益和验收方式；评估无需实施时记录理由即可。

| 候选 | 进入条件与任务 | 回归要求 |
| --- | --- | --- |
| 工具结果索引化 | 恢复解析耗时明显时，用 toolCallId 索引及最近 assistant 指针替代重复复制、扫描 | 保留缺失 ID、重复 ID、未匹配结果的既有回退行为与顺序 |
| 日志与渲染更新收敛 | 日志或无关状态造成大量提交时，将日志独立缓冲、按需批量刷新；稳定关键 props、回调和订阅 | 诊断信息完整、缓冲有界；旧批次日志不进入当前会话；不通过错误 memo 比较隐藏必要更新 |
| 消息和侧栏虚拟化 | 全量挂载、布局占据主要成本时，仅挂载可见范围与适量 overscan，支持动态高度 | 流式追加、图片加载、代码展开、滚动锚点、回到底部、键盘可达和跨虚拟边界的回合信息正确 |
| 延迟高亮与 Worker | 同步 JSON 解析、历史归一化或高亮形成长任务时，评估分块、可见后高亮或 Worker | 过期批次可丢弃；若 JSON.parse 是瓶颈，需转移原始解析，不能主线程解析完才交给 Worker；计入传输成本 |
| 索引持久化合并 | JSON.stringify/localStorage 写入有明确成本时，合并无变化更新或批量保存 | 验证正常退出与存储失败；不能仅依赖组件卸载防止数据丢失，说明异常退出下的持久化边界 |
| 原生启动取消 | 启动/退出等待仍主导加载耗时时，实现取消登记与迟到进程回收，再评估是否允许启动和清理重叠 | 取消先于进程登记也有效；超时或 Promise.race 不算实际取消；验证共享配置、资源互斥、进程树与监听器清理 |

本 feature 不包含多会话后台生成、会话保活池或新的全局状态管理框架。`startTransition` 可用于可中断的 React 更新，但不能作为同步解析、高亮或进程取消的替代。

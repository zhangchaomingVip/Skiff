# 013 · 航行台工具弹幕与阶段计时隔离

状态：已实施；自动化与浏览器验证完成，未验证项目见 verification.md。创建日期：2026-10-11。

## 背景与目标

航行台目前用同一套活动状态展示思考、工具执行和整轮航行时间。阶段切换、连续工具调用、并行工具以及结束事件重复到达时，三个数字可能互相串用或跳回较小的值。工具等待也缺少独立的可视轨迹，用户难以判断哪些调用仍在运行、哪些已经完成或失败。

本 feature 将工具执行做成带航行气质的“工具航迹带”：每个工具调用从上方落下一行，长调用浮在活动区并显示自己的秒数，完成后沉入航海日志；短调用快速掠过，避免仪表盘因 `sleep 1` 一类调用频繁抖动。同时重建阶段计时模型，保证思考、工具和整轮航行各自单调、独立、可冻结。船速表只在输出阶段更新。

本 feature 只改前端计时、航迹展示和测试，不新增 RPC、Rust 接口或持久化字段；已有上下文用量、速度统计和钓鱼等待态继续保留并与新状态组合。

## 行为约定

### 1. 独立的航行时间线

- 每次 `activeRun` 建立唯一时间线键，至少由 `turnId`、提交时间和 prompt 标识组成；新 run 建立新账本，会话切换立即丢弃旧账本。
- `航行` 从 run 的 `startedAt` 开始，覆盖提交等待、思考、工具和输出，直到成功、失败、超时、中止或 bridge 退出时冻结。后续重复结束事件不得继续增长或覆盖已结算值。
- `思考` 按阶段片段累计。思考 → 工具 → 思考时，第二段思考接着累加，不把前一段归零；缺少明确事件时沿用现有消息推断，但不得把工具等待误报成思考。
- `工具` 按调用批次累计墙钟时间。一个批次内的并行调用从最早未完成调用开始，到该批次全部进入完成、失败或超时状态结束，避免并行调用被错误相加。
- 每个工具调用另有独立生命周期：`startedAt`、终态时间、终态类型和稳定的 `tool id`。调用失败、超时、缺少结果或结果迟到都必须有确定的收尾规则。
- 计时只使用一个统一刷新器；run、阶段或组件卸载时统一清理。禁止为每个工具行创建独立 interval，禁止在 render 中复用会被下一阶段覆盖的计时器起点。
- 展示值必须单调：活动阶段只能增长，阶段切换不能把其他阶段改小；结束后固定最后一次有效读数。系统时间调整、重复消息和旧 run 事件不能造成倒退。

### 2. 工具弹幕 / 航迹带

- 活动工具区位于航行台的海面或航迹区域。新调用从上方进入并向下落一行，随后把已有活动行向下顶；同一调用的后续事件只更新原行，不重复创建。
- 每行至少显示工具名、简短目标或参数摘要、运行状态和自己的计时状态。并行调用同时保留多行，并按调用出现顺序稳定排序。
- 计时低于 5 秒只是展示阈值，不改变真实计时：活动行显示“执行中”或短暂动效，不显示 `0s`、`1s` 等数字；超过 5 秒后固定在活动区并显示自己的秒数。
- 短调用完成后快速下沉，不在活动区停留；随后以紧凑的航海日志行保留“已完成”记录，不显示无意义的短秒数。
- 长调用完成、失败或超时后从活动区沉底进入日志，保留最终耗时。失败和超时使用明确但不刺眼的警示色和文案，不能静默消失。
- 日志按完成顺序追加并保持可读；活动区和日志区都必须有界，必要时限制可见行数并支持滚动或折叠，不能让单轮大量工具调用撑爆布局。
- 动画遵循 `prefers-reduced-motion`：减少动态效果时取消坠落、浮标和沉底过渡，直接呈现正确顺序、状态和计时。
- 文案保持航行主题，例如“工具航迹”“执行中”“已入日志”，但状态含义必须比装饰更清楚；屏幕阅读器应能读到工具名、状态和最终结果。

### 3. 船速表边界

- 实时船速、指针、尾流和海浪只在输出阶段（可见回复文字产生增量）更新。
- 思考、工具执行、等待首个输出和停泊阶段船速显示为 0 或静止占位，不因思考文字、工具参数或 usage 修正乱动。
- 已结束本轮的平均速度和峰值可以继续展示历史结果；usage 校正不得重新制造峰值，也不得改变已经冻结的阶段计时。

## 验收矩阵

| 场景 | 必须验证 |
| --- | --- |
| 提交后等待首个输出 | 航行从提交开始；思考、工具尚未启动时各阶段不互相显示时间 |
| 思考 → 工具 → 思考 | 思考时间累计；工具时间独立；航行时间连续增长 |
| 单个工具 < 5s | 活动行快速掠过，不显示秒数；完成记录沉底留档 |
| 单个工具 ≥ 5s | 活动行浮住并显示自己的秒数；完成后冻结并沉底 |
| 多个并行工具 | 每行独立计时；批次时间按墙钟统计；完成顺序稳定留档 |
| 工具失败 / 超时 | 行显示终态、颜色和冻结耗时；不会让其他行或航行计时倒退 |
| 工具结果迟到 / 重复结束 | 原行只收敛一次；旧事件不能污染新 run |
| 工具等待无输出 | 船速为 0 且仪表静止；工具航迹继续按规则计时 |
| 输出阶段 | 船速表、尾流和海浪才更新；输出暂停时不把工具或思考误算成速度 |
| 正常结束、取消、bridge 退出 | 所有阶段固定；统一刷新器和监听器清理干净 |
| 新 run / 会话切换 / 卸载 | 旧行、旧计时和旧速度不残留；新 run 从自己的起点开始 |
| 窄屏与减少动态效果 | 无横向溢出；无动画时顺序和状态仍清楚，日志可访问 |

## 验证要求

- 所有自动检查记录实际命令和结果，不预先填写通过状态；未验证的真实 pi、Tauri/WebView2 或屏幕阅读器行为明确列出。
- 可控时钟测试必须断言 4 个边界：4999ms 不显示秒数、5000ms 显示秒数、并行工具的批次墙钟时间、终态后不再增长。
- 视觉截图需同时包含活动区和沉底日志，至少保留一个并行调用、一个失败或超时调用以及一个减少动态效果版本。
- 不以截图代替计时正确性；不以 interval 数量为零代替工具状态已正确收尾，二者分别验证。

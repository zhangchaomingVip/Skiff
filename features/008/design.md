# 008 · 模型优先的任务入口与对话界面

008 将 Skiff 的新任务入口重构为“模型优先”。用户打开新聊天时，先看到可用模型和线路，再进入具体会话；已有会话仍以项目和任务为上下文，不因模型优先而改变历史结构。

设计参考：[模型优先方案预览](../home-demo-model-first.html)。预览文件只用于交互和视觉对比，正式实现必须使用运行时 offers、真实项目、真实会话和已有的用量数据。

## 目标与核心原则

- **模型是新任务的第一入口**：用户可以先比较模型能力、上下文和价格，再开始聊天。
- **任务和项目仍是会话主体**：模型切换不创建新会话；项目工作目录始终明确显示。
- **Offer 是真正的选择单位**：视觉上可以按模型聚合，实际选择继续引用 `offerId` / `routeId`。
- **真实线路优先**：卡片、聊天标题、最近会话和回复用量都显示实际线路；历史费用使用不可变的 `RouteSnapshot`。
- **复用现有能力**：继续复用 `Sidebar`、`ModelPicker`、`VoyageWorkspace`、`useModelFamilies` 和 `workspace` 数据，不复制两套模型选择逻辑。
- **渐进增强**：模型加载、线路配置、历史用量缺失时仍能完成基本聊天，不因为主页信息不完整而阻塞用户。

## 术语

- **模型家族**：用户熟悉的品牌或能力归属，例如 DeepSeek、Kimi、GLM。
- **模型**：家族下的实际模型 ID，例如 `deepseek-v4`。
- **Offer**：`routeId × modelId`，包含线路、模型、能力、价格和扣费账户，是聊天真正选择的对象。
- **主页 / Launcher**：模型优先的新任务入口，不等同于会话本身。
- **聊天页**：当前项目中的具体任务会话，保留消息、工具、输入框和航行台。

## 信息架构

```text
应用壳
├── 侧栏
│   ├── 主页
│   ├── 新聊天
│   ├── 项目

```

现有项目侧栏继续承担会话管理、搜索、固定、重命名和删除。008 不再引入“按时间 / 模型 / 项目”三套并行导航；模型筛选属于主页和模型选择器的能力。

## 主页 Launcher

### 顶部区域

主页顶部显示：

- 页面标题“选择一个模型，开始工作”。
- 一句说明：模型负责执行，项目负责上下文，会话保留完整历史。
- 当前工作区选择器，默认使用当前项目；允许切换项目或添加项目。
- 设置、主题等全局操作沿用现有标题栏。

点击“新聊天”进入 Launcher。应用启动时默认恢复上次会话；如果没有可恢复的有效会话，显示 Launcher。

### 模型卡片

卡片以模型家族聚合，卡片内部显示默认 Offer 和可用线路数量。卡片至少展示：

- 家族名称、图标、显示名和实际模型 ID。
- 可用状态：可用、加载中、未配置、已禁用或连接异常。
- 能力标签：工具、视觉、推理、流式和上下文窗口。
- 默认线路、线路数量和扣费账户状态。
- 输入 / 输出单价，格式为“入 ¥x · 出 ¥y / 百万 token”。
- “开始聊天”主操作；多线路时提供“选择线路”次操作。

卡片不直接写死 DeepSeek、Kimi、GLM 数量，数据来自有效 `RuntimeOffer`。建议主页优先显示最近使用或推荐的 4～6 个模型，其余通过“查看全部模型”和搜索访问。

### 开始聊天

- 当前项目明确时，点击“开始聊天”创建或复用该项目的空草稿，并钉住选中的 `offerId`。
- 一个模型只有一条有效线路时，直接使用该线路。
- 一个模型存在多条线路时，先打开线路选择浮层；不能静默改变扣费主体。
- 当前项目不存在时，先要求选择项目；不能把模型卡片点击默认为未知工作目录。
- 卡片点击不会自动发送消息，进入聊天页后由用户输入任务。

### 外部 Agent

Codex CLI 等本地外部 Agent 单独归入“外部 Agent”视觉分组。显示执行方式和配置来源，不伪造普通模型的上下文、线路或价格字段。

## 最近会话

最近会话继续使用现有会话索引，行项目展示：

- 会话标题和最近内容摘要（有数据时）。
- 项目名称、更新时间。
- 最后一条完成回复的家族、模型和实际线路。
- token 和费用摘要（有可靠缓存时）。
- 继续入口，以及错误或线路失效状态。

历史线路和费用必须使用会话中的 `RouteSnapshot`。当前配置改名、改价或删除线路后，历史行不能被当前配置覆盖。

现有 `Conversation` 没有完整的累计 usage 摘要时，首版只显示标题、项目、时间、模型和线路；不使用不可靠的估算数字。后续可以增加本地缓存的 `usageSummary`，但不能取代消息级快照。

## 聊天页调整

聊天页保留当前消息、工具、Markdown、附件、命令和输入框能力，调整以下展示：

- 顶部同时显示会话标题、项目、家族、模型显示名和实际线路。
- 输入框模型按钮继续打开现有 `ModelMenu`，每一行代表一个 Offer。
- 手动切换模型仍留在当前会话，不返回主页，也不创建新会话。
- 每条完成回复继续展示真实线路和价格快照；切换审计沿用 007。
- `VoyageWorkspace` 和 `VoyageRail` 继续只服务聊天页；主页不复制完整用量台。
- 线路切换、失效回退和跨账户授权沿用 007 的状态机。

## 状态与数据设计

### Launcher 状态

当前 `useWorkspace` 会始终保留一个空草稿，因此不能用 `activeChat === undefined` 推断主页。应用壳需要显式维护视图状态，例如：

```text
view: "launcher" | "chat"
```

规则：

- `activeChat` 继续表示当前会话，不因进入 Launcher 被清空。
- 选择最近会话将 `view` 切换为 `chat`。
- 点击主页或新聊天将 `view` 切换为 `launcher`。
- Launcher 创建聊天后立即切换为 `chat`，并传入选定 Offer。
- `Ctrl+N` 打开 Launcher；若后续确认需要保持旧行为，可改为直接复用当前项目草稿。

### 数据来源

- 模型卡片：`modelFamilies.offers`，以 `offerId` 去重并根据有效状态过滤。
- 最近模型：现有 `recentOfferIds`。
- 当前项目和聊天：`useWorkspace`。
- 历史实际线路：`Conversation.routeSnapshots`。
- 当前聊天用量：`useVoyageMetrics` 和消息级 usage。
- 模型选择浮层：复用 `ModelPicker` / `ModelMenu`，不新增第二套搜索、键盘和消歧规则。

### 配置加载状态

主页必须覆盖以下状态：

- 配置加载中：显示卡片骨架或加载提示。
- 没有启用线路：显示空状态和“管理提供商”。
- 配置读取失败：显示错误原因和重试入口。
- 当前会话模型失效：主页提示失效原因，聊天页执行 007 的一次性回退提示。
- 外部 Agent 可用但无价格：显示“由外部 Agent 管理”。

## 视觉与响应式

- 沿用现有 CSS 变量、明暗主题、圆角和间距体系；预览中的独立样式只作为参考。
- 桌面宽度优先使用三列模型卡片，较窄窗口变为两列，再变为单列。
- 侧栏在窄窗口收缩或复用现有抽屉行为；主页内容不被固定宽度卡片撑破。
- 模型卡片需要明显的 hover、focus、selected 和 disabled 状态。
- 线路和扣费账户信息不能只依赖颜色；必须有文字或标签。
- 不在主页复制航行台的动态图形和完整明细，避免模型卡片、历史会话和用量信息争夺主层级。

## 键盘与可访问性

- 模型卡片和最近会话都可通过 Tab 聚焦，Enter 执行主操作。
- 线路选择浮层支持方向键、Enter、Escape，边界定位沿用 `ModelPicker`。
- 项目选择器具有可读的 label 和当前值。
- 所有状态只通过颜色表达时，补充文本或图标标签。
- `prefers-reduced-motion` 下关闭卡片浮起和页面过渡。

## 非目标

- 不在 008 中重写 pi RPC、线路授权状态机或模型发现协议。
- 不把项目导航改为按模型永久分组。
- 不在主页实现完整费用报表、账单管理或跨会话分析。
- 不自动重发用户消息，也不因模型卡片点击自动发送内容。
- 不删除现有 `home-demo.html`；预览稿和正式实现并存，直到方案验收完成。

## 验收标准

1. 用户能从主页选择项目、模型和具体线路，在两步内进入可输入的聊天页。
2. 多线路模型不会静默改变扣费账户；卡片和浮层能读出线路、价格和能力。
3. 从最近会话进入后，能恢复项目、标题、当前模型和实际历史线路。
4. 手动切换模型留在当前会话，消息历史不丢失，Offer 和 routeId 正确保存。
5. 线路禁用、配置为空、配置加载中和加载失败都有可理解的 UI 状态。
6. 主页、线路浮层、最近会话和聊天页在明暗主题及窄窗口下可用。
7. `npm run build`、`npm test`、Rust 检查和浏览器预览回归通过。

## 008 执行记录

### 第 0 段：交互契约与基线（2026-10-05）

本段冻结以下规则，后续实现和验收均以此为准：

- 应用壳显式维护 `view: "launcher" | "chat"`。启动时恢复上次仍存在的有效会话；没有有效会话时进入 Launcher。
- `activeChat` 始终表示当前会话，进入 Launcher 不清空它。主页和“新聊天”切到 Launcher；选择最近会话切到 chat；Launcher 创建或复用草稿后切到 chat。
- `Ctrl+N` 固定打开 Launcher。Launcher 使用当前有效项目；同一项目已有空草稿时复用它，否则创建一个空草稿。没有有效项目时阻止开始聊天并要求选择项目。
- 模型卡片以有效 `offerId` 为选择单位，按家族和 `modelId` 聚合。单线路直接使用该 Offer，多线路必须打开线路选择；禁用线路不进入可选集合。
- 主页默认按 `recentOfferIds` 优先排序，其余 Offer 保持运行时目录顺序；不写死家族或线路数量。外部 Agent 单独展示，不伪造普通模型价格和上下文字段。
- 最近会话首版只展示可确认的标题、项目、更新时间、模型和实际线路；历史线路和费用优先使用会话内 `RouteSnapshot`。未可靠缓存的 token/费用不显示估算数字。

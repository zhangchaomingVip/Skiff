# 003 · 推理、用量、提供商与图片

## 交互

- 输入框底栏的模型按钮打开浮层，分别选择模型与推理等级。等级通过 pi `get_available_thinking_levels` 获取，设置后读取 `get_state` 确认实际生效值；无推理能力的模型显示「不支持推理」。
- 输入框下显示累计 Token 与累计生成耗时，点击 Token 打开明细：输入（缓存命中/未命中/写入）、输出（推理/回复）、缓存命中率与比例条。pi 的 `input` 是未缓存输入，`output` 已包含推理，不能重复累计。未报告的推理拆分显示「未提供」。
- 顶部设置按钮打开提供商管理：名称、Base URL、API Key、模型 ID、推理与图片能力。Base URL 使用 OpenAI Chat Completions 的 API 根地址（如 `/v1`）；支持 `/models` 自动发现，失败可手动输入。更新既有配置时空 Key 保留原凭据。
- 图片可通过文件选择、拖放或粘贴加入输入框，发送前预览并可删除。支持 PNG/JPEG/WebP/GIF，最多 4 张、每张 5 MiB；不支持图片的模型禁止发送附件并提示切换模型。消息与历史记录显示图片。

## 数据与安全

- 所有模型调用继续经 pi RPC；图片按 `images: [{type:"image",data,mimeType}]` 发送，不另建模型调用链。
- 提供商由 Rust 合并到 pi `models.json`；凭据保存在 pi `auth.json`。不回传已保存 Key、不写 localStorage/聊天日志、不执行输入的 shell 命令。保留其他提供商与未知字段，使用临时文件替换；尊重 `PI_CODING_AGENT_DIR`。
- 自动发现请求由 Rust 发往用户填写的地址，禁止重定向，设置超时；错误只显示状态与简短说明，不输出响应正文或密钥。
- 耗时包含生成与工具执行，停止/失败也计入；索引保存累计耗时，不保存图片。历史 Token 从 pi 消息重新统计。

# 014 · 航行台统计与工具日志展示优化

状态：已实施，自动化与浏览器验证通过。创建日期：2026-10-11。依赖 `012-voyage-experience` 与 `013-voyage-tool-waterfall` 的航行台实现。

## 背景与目标

航行台的上下文数字在同一次航行中会在 `0.0%` 与较大 usage 之间跳动，工具航迹在没有参数摘要时显示「等待参数」，本次航行记录缺少输入和思考 Token，工具失败次数也没有在日志摘要和展开列表中突出。

本 feature 统一前端展示口径：当前航行内所有 assistant 请求的完整输入量（`input + cacheRead + cacheWrite`）累计计算，包含工具往返请求；上下文读数保持单调；航行记录展示输入、思考和输出 Token；工具日志直接从已有终态统计失败并显示明确状态。

本 feature 只改前端统计与 UI 展示，不改变工具调用行为、RPC、Rust 接口或持久化字段。

## 行为约定

- 上下文和输入 Token 统一按每个 assistant 请求的 `input + cacheRead + cacheWrite` 累计。
- 工具往返产生的 assistant 请求输入必须计入同一航行。
- 同一航行内上下文读数只能增长或保持稳定；重复或较小的流式 usage 不得造成回退。
- 思考 Token 使用 `usage.reasoning`；缺失时显示 `—`。
- 没有 usage 时允许本地估算，估算包含文本、思考、工具参数和工具结果，并明确标记为估算。
- 无目标参数时工具行只显示工具名称，不显示「等待参数」。
- 失败次数统计航海日志中所有非 `completed` 终态：`failed`、`timeout`、`interrupted`、`missing`。
- 日志标题显示 `航海日志 · N 项已入日志（M 次失败）`；失败数为零时隐藏括号。
- 失败、超时、中止、缺少结果的列表项必须有明确可见状态。

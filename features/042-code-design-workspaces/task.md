# 042 · Code / Design 双工作区

日期：2026-11-13。

## 导航与状态

标题栏紧跟在折叠侧栏图标之后提供 Code / Design 分段控制器（图标 + 文本，半透明轨道、选中项为浮起的白色/浅色块），标题栏不再常驻文件 / 编辑 / 帮助菜单。Activity Bar 只承担一级视图（对话 / 文件，或生图 / 生成视频），同一时刻仅有一个选中项。Code 保留工程会话、项目与文件、Commit / Diff / Git Tree、航行台及浏览器能力。生成画廊移除「返回对话」，通过顶栏的模式切换回到 Code。

`useWorkspaceMode` 维护 `workspaceMode: "code" | "design"`、独立的 `codeTool` / `designTool`，保存在 `skiff.workspace.navigation.v1`。旧工具偏好自动映射到对应模式，损坏或未知值回退到 Code。旧偏好键仍同步当前工具以保留兼容性。

Code 和 Design 分别记忆导航侧栏的开合与宽度。Design 的图片/视频草稿与参考图独立，浏览分组分别持久保存；草稿和参考图继续沿用运行期保留的语义，不把 blob URL 写入存储。模式切换保留聊天草稿、文件预览、滚动位置及任务，不重启 pi，不重发付费生成请求。

`WorkspaceRoute` 与 `DesignWorkspace` 为独立的保留型路由边界：隐藏时保留组件状态，推迟隐藏视图的父级属性更新，恢复时接收最新快照。pi 运行池和生成任务观察留在路由之外。Code 隐藏时暂停浏览器画面轮询，保留浏览器进程；隐藏侧栏不会因窗口变窄而打开模态抽屉。

## Design / Studio

- 导航侧栏：文生图 / 图生图 / 视频入口、全部作品 / 进行中 / 失败记录 / 已移除，以及任务统计。设计室不绑定 Code 项目，也没有项目选择器。
- 主区：可调宽度的参数表单与瀑布流结果；图片保留实际比例并按容器宽度调整列数，使用懒加载和异步解码。图片/视频结果路由分别保留，切换时保留各自浏览位置。
- 空间不足时，创作参数使用独立抽屉；配置服务后可恢复原参数抽屉。Design 导航与参数抽屉分别管理。Light / Dark、600px 和 390px 布局沿用现有设计 Token。
- 复用现有图片并发 3 / 5 / 10 / 不限（默认 5）、逐任务停止等待、失败历史，以及视频远端排队、暂停/恢复、下载重试与重启恢复语义。

## 单向发布

生成任务保留可选 `projectRoot` 本地元数据，提交时记录当时的项目，仅作任务信息使用；不发送到模型服务。旧任务记录仍可读取。

图片作品菜单/预览、视频作品提供「保存至当前项目」，将已落盘的原件复制到当前项目 `assets/`，完成后可「在 Code 中查看」。原件保留，同名目标自动添加数字后缀；保存后刷新文件树与 Git 状态。未关联项目时禁用保存；运行期临时导入的内容沿用既有语义，不伪装成已持久保存的资产。

反方向不成立：Design 不镜像 Code 项目图片。没有项目选择器、没有启动基线、没有文件变更后的扫描归档、也没有「来自 Code / 当前项目」分组与「同步项目图片」入口；画廊只包含工作室生成或用户在当前会话导入的作品。项目目录里的 PNG / JPEG / WebP 不会出现在设计室。

## 原生边界

`design_assets.rs` 只保留「保存到项目」这一条命令。项目路径复用原工作台 canonicalize/边界检查；复制来源必须是生成目录 `assets/` 中的受控原件，不能借此读取任意本机路径。目标使用 `create_new` 防覆盖并以流式复制控制内存，支持现有视频的 256 MB 上限；失败清理本次部分文件。项目扫描、资产库记录与移除状态已随双向联动一并移除。

原件位于既有 asset scope 下，命令注册只保留 `save_design_asset_to_project`，没有增加进程执行能力或扩大全局文件访问权限；测试使用临时项目、生成目录、pi 目录与 WebView2 profile。

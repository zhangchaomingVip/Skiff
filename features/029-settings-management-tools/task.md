# 029 · 设置批量管理与使用记录（第二期）

状态：待实现，依赖 028。创建日期：2026-10-19。

来源：[设置改版预览附录](../../tests/settings-redesign-preview.html)及需求评审。第一期见 [028 · 设置三模块信息与交互整理](../028-settings-information-redesign/task.md)。本期在第一期的信息与状态约定上增加批量管理、测试记录、使用排序及路线顺序编辑，不重复重做三页布局。

## 背景与目标

供应商与路线增多后，逐项启停、反复测速和大量排序操作成本上升。目标是让用户批量管理接入配置，查看可信的历史测试记录，并明确区分「页面显示顺序」与「实际故障切换顺序」。所有记录仅本地保存，不改变模型推荐、费用计算或路由授权。

## 范围与行为约定

### 1. 供应商批量启停与删除

- 第一版批量操作仅覆盖供应商列表，不扩展到模型清单或路线批量编辑。增加显式「批量管理」入口；进入后复选框常驻，键盘可操作，不依赖 hover 才能发现。
- 选择以供应商稳定 ID 维护；全选仅选择当前搜索/筛选结果。改变搜索、状态或来源分组范围时清空选择，排序不清空选择；退出批量模式或离开页面清空选择。批量条显示选中数量。
- 批量启停只改供应商 enabled，不改路线自身开关、默认路线和模型剔除配置；操作前说明受影响的供应商数量，停用时同时提示影响的路线数与默认路线。
- 删除确认展示供应商名称、关联路线数及默认路线影响。若所选供应商包含任何默认路线，整批禁止删除，并提供去对应家族调整/显式清空默认值的入口；不自动替换或清空默认值。
- 批量写入由原生层一次验证、一次应用，全部成功或全部不变。无效 ID、默认路线保护或保存失败时显示具体原因并保留选择；不能在前端并发调用单条接口造成部分成功和状态覆盖。
- 原生提交时重新验证最新配置；确认期间对象消失或默认值改变时终止操作并刷新预览。成功后刷新配置和 runtime offers 一次并清空选择；失败不报告成功数量。
- 沿用设置运行中/加载中限制、pending 防重入和删除确认。批量操作不承诺回收站或撤销，删除影响必须在提交前说明。

### 2. 最近测试记录与失效规则

- 记录「最近一次完成的测试」，同时包含成功和失败；取消不写成失败，也不覆盖已有结果。不把最近一次成功伪装成最近一次结果。
- 记录至少包含供应商 ID、实际模型 ID、测试完成时间、成功/失败、延迟、HTTP 状态或脱敏错误类别，以及用于校验目标是否变化的配置版本信息。路线视图通过关联供应商与实际模型查询，不把一个模型的成功扩散到整条路线的所有模型。
- 供应商行显示最近一次测试的摘要，详情注明模型；路线行只能取该路线仍配置的模型记录。模型页使用第一期解析出的具体测试目标查询记录。没有记录显示未测试，不展示虚构健康状态。
- 延迟表示现有连接测试请求耗时，不标成吞吐量或首 token 延迟。超过 7×24 小时提示「记录已过期，建议复测」，历史成功不代表当前在线。
- 端点、密钥、协议或超时改变后旧记录标为配置已变化；模型 ID 改变后不沿用旧 ID 的结果。只改名称不失效；价格和显示名改变不使连接结果失效。
- 测试开始时绑定目标与配置版本，完成时再次核对。重叠测试按发起顺序保护，旧请求晚返回不得覆盖更新请求的结果；取消/组件卸载遵守现有停止语义。
- 新建供应商及已修改连接字段的未保存草稿只保留临时结果；保存成功后仅把与最终配置一致的已完成结果转为持久记录，取消编辑不污染已保存配置的历史。
- 历史缓存不参与新增供应商的通过测试判定，不作为自动剔除、故障切换或重试依据；不新增后台自动测速或定时请求。

### 3. 最近使用与供应商展示排序/分组

- 「最近使用」定义为实际聊天通过该路线成功收到一次模型响应的时间，记录对应供应商和路线；选择模型、打开设置、连接测试、历史会话恢复、失败且无有效响应均不计入。工具调用响应属于有效模型响应，每次响应只更新一次，不按流式片段频繁写盘。
- 自动故障切换后只更新实际产生响应的目标；多个会话更新同一对象时保留较新的时间。无法可靠归属到受管理路线的响应不猜测归属。
- 提供商展示排序增加按名称、最近使用、状态；默认保持配置原顺序。最近使用降序，未使用项置后；状态排序启用在前；同值保持配置原顺序，避免列表抖动。
- 来源分组为可选视图，默认不分组；启用后按官方直连、中转、本机、自定义分组，沿用第一期来源判定，组内应用选定展示排序。无结果不显示空分组。
- 名称/状态排序只在内存派生，最近使用读本地记录；展示排序与分组偏好可用独立版本的前端偏好保存，不能重排 FamiliesConfig 中任何数组。模型页不增加无意义的排序控件。

### 4. 调整路线切换顺序

- 在单个家族中提供「调整切换顺序」模式，展示该家族全部路线，包括停用、提供商停用及未配置模型的路线，并明确顺序影响同实际模型 ID 的故障切换。
- 进入模式后使用完整家族列表，暂不应用搜索/可用筛选；保留进入前筛选值，退出后恢复，防止隐藏路线被意外丢失或换位。
- 支持拖动和等价键盘上移/下移，操作先改变本地草稿，点击保存后一次提交完整路线 ID 顺序；取消、Esc 或退出不保存。排序模式期间锁定外层分类与冲突编辑。
- 原生提交重新验证路线集合和完整性。排序期间外部配置增删路线时拒绝旧顺序并提示重新加载，不静默合并。写入失败保留排序草稿以便重试。
- 拖动不改变默认路线、不改变路线内模型顺序、不启停路线、不重新固定已有会话。清空默认仍沿用第一期独立确认，不混进排序保存。
- 不改现有故障切换算法：只向后选择、相同实际模型 ID、满足能力要求、不绕回首条；不同/未知扣费账户仍需原有授权。

## 接口、持久化与兼容

- 批量供应商命令接收供应商 ID 集合与操作类型，复用现有原生配置校验/写入路径；响应返回最终配置，失败返回可展示的原因。前端 hook 统一处理 pending、配置刷新和错误，不把并发单条写入当作批量接口。
- 测试与使用记录由原生层管理，保存在当前 pi agent 目录内独立的版本化本地元数据文件，尊重 PI_CODING_AGENT_DIR；通过专用查询/记录接口与前端和会话生命周期对接。不写进 pi 的 models.json/auth.json，也不改变现有家族配置格式。
- 目标版本或失效标识在原生层维护，不向前端返回真实密钥或持久化密钥副本；记录中不保存原始请求、响应正文、带凭据 URL 或未脱敏服务端错误。复用已有安全处理边界。
- 元数据缺失或损坏时降级为无记录，不阻止配置读取、聊天或测试；原子写入并合并并发更新，记录落盘失败不把已经成功的模型请求改判为失败。
- 删除供应商/路线或移除模型后清理无引用元数据；新对象不继承同名旧对象记录。旧用户无需手工迁移，第一次使用从无记录开始。
- 若修改 native 命令注册或权限，检查 src-tauri/capabilities/，只开放本功能所需访问。同步更新 TS 类型与 mock bridge，单项设置入口继续可用。

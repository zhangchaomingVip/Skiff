# 032 · 多项目侧栏、文件预览与 Git 操作

状态：已实现，待补充自动化 CDP 与 200% 缩放验收。创建日期：2026-10-28。

来源：侧栏改版需求讨论。参考 IDEA 的工具栏、文件树与变更列表，以及 Codex 的双层侧栏和顶部下拉样式。本文记录确认后的首版范围与实施默认值，作为后续实现和验收依据。

## 目标与首版范围

在左侧增加固定工具栏，从上到下依次为「会话」「文件」「Git」，工具栏背景比内侧面板深一档。会话保留现有形态；文件与 Git 共用独立的项目下拉，默认查看当前聊天所属项目，也能浏览其他项目而不切换聊天。

文件支持懒加载目录树和只读预览，跨项目最多打开 3 个文件，按首次打开顺序淘汰。Git 提供 Diff、Rollback、Add 和按文件选择提交，用户填写 commit 信息后创建本地提交。界面不提供暂存区管理，也不展示「已暂存 / 未暂存」两组列表。

本期不包含文件编辑与保存、文件新建/重命名/删除、按行或改动块提交、分支切换、历史回退、冲突解决、push/pull、自动提交和模型生成 commit 信息。未跟踪文件的删除不包含在 Rollback 内。

## 1. 双层侧栏与会话迁移

- 桌面布局为「固定工具栏 → 当前工具面板 → 主工作区」，沿用顶部标题栏及右侧航行台。
- 工具栏建议宽 48px，图标顺序固定为会话、文件、Git。使用现有图标体系，必要时补 Git 图标；提供名称提示、键盘焦点和明确的选中状态。
- 浅色、深色主题分别定义工具栏语义色，均比内侧面板更深；使用 tokens，不照搬截图中的品牌色或写死单主题颜色。
- 点击另一个工具切换面板并展开；再次点击已展开的当前工具收起面板，保留工具栏。顶部原侧栏开关控制内侧面板，重新展开时回到上次工具。
- 复用现有调宽组件；新用户面板建议默认 280px，桌面可调范围沿用 200–420px，兼容已有合法宽度偏好。计算可用空间时扣除工具栏和分隔条，保留聊天最小宽度及航行台的空间不足回退。
- 窄屏沿用抽屉，工具入口仍可访问，抽屉中可切换工具；不把固定面板挤进聊天区，不显示桌面调宽把手。关闭后焦点回到触发入口。
- 会话面板保留新聊天、主页、项目/会话列表、最近、搜索、固定、归档、批量操作及运行状态。
- 保留已调整的会话箭头行为：普通项目行不显示箭头，「项目 / 最近」标题箭头在悬浮或键盘聚焦时出现。文件树目录的展开箭头独立保留。
- 切换或收起工具时保留会话搜索、滚动位置和展开状态；不卸载会话运行池、不重连 pi、不丢失聊天草稿。

## 2. 文件与 Git 共用项目下拉

### 项目选择与跟随

- 下拉位于文件/Git 面板顶部，主文案为项目名称，选项辅助展示路径并标明当前选择，支持同名项目。
- 选项来自现有可见项目列表，不新增一套项目注册表。
- 2026-10-29 补充：可见项目最多 5 个；满额后添加时明确选择一个移出列表，保留聊天、草稿和本地文件。已有超过 5 个的列表先由用户选择整理，不自动淘汰。重新添加同一路径恢复已有项目。
- 浏览项目状态与当前聊天项目独立。切换下拉只影响文件树和 Git，不调用会切换/创建聊天的项目选择逻辑。
- 初始进入「跟随当前项目」模式，展示当前聊天所属项目；此时切换聊天项目，浏览项目同步更新。
- 用户手动选择项目后进入「手动选择」模式，切换聊天不改变浏览项目。提供「回到当前项目」入口，点击后恢复跟随模式。
- 文件与 Git 共用浏览项目和跟随模式；从文件切到 Git 时保持同一目标。
- 当前项目不存在时显示选择项目的空状态；手动选择的项目被隐藏/移除后清除失效目标，回退到可用的当前项目或空状态，不静默选择其他仓库执行操作。

### 状态保存与请求归属

- 工具模式、面板开关与宽度可使用独立版本的本地偏好保存；不改写 workspace v1 中的聊天归属。
- 首版浏览项目、跟随模式和预览标签在应用运行期间保留，重新启动默认恢复跟随当前项目。
- 文件树展开、滚动位置按项目维护。Git 提交信息按项目及实际仓库保存为运行期草稿，切换面板/项目后可以恢复。
- Git 文件选择绑定项目、仓库和状态版本，不随项目切换迁移；切换目标时清空选择，保留提交信息草稿。
- 异步查询和写操作均绑定发起时的项目/仓库，迟到结果不能覆盖新项目。提交期间切换视图不会改变命令目标，结果显示其实际项目名称。

## 3. 文件树与只读预览

### 文件树

- 以选定项目目录为根，显示文件夹和文件；文件夹优先、名称排序稳定。目录按展开加载，不在打开面板时递归扫描全项目。
- 提供刷新、全部折叠、加载中、空目录、无权限、路径失效及失败重试状态。
- 长文件名可截断，完整路径通过提示查看。文件类型用现有图标体系表达。
- `.git` 内部目录不作为普通项目内容展开。大型依赖/构建目录不主动遍历；单目录结果和文件读取设置合理上限，截断要明确提示或提供继续加载。
- 符号链接与 Windows junction 不得使读取逃出所选项目根目录或形成循环；首版可展示链接但不跟随目录链接。
- 项目切换或组件关闭后取消查询或忽略过期结果，释放监听和缓存中的无用内容。

### 最多 3 个预览标签

- 点击文件打开只读预览。预览区作为主工作区的可关闭视图，提供明确的「返回聊天」入口；聊天运行与草稿保持，返回时恢复原阅读位置。
- 首版文本/代码显示行号和语法高亮；大文件、二进制、无法解码文件显示基础信息及无法预览原因，不强行渲染完整内容。文件内容按文本处理，不执行 HTML 或脚本。
- 全应用跨项目合计最多 3 个文件预览标签，不是最多 3 个项目，也不是每项目 3 个。
- 按首次打开顺序执行 FIFO：打开 A、B、C 后再查看 A，顺序仍为 A、B、C；打开 D 后关闭 A，剩下 B、C、D，并激活 D。
- 重复打开同一个项目中的同一文件只激活已有标签，不重复占位，也不更新淘汰顺序。主动关闭后再打开，视为新打开。
- 标签身份至少包含项目标识和规范化相对路径，跨项目同名文件不合并；标签显示文件名，提示显示项目和完整路径。
- 切换浏览项目不关闭已有标签；点击其他项目的标签只切换预览，不改变聊天或下拉选择。
- 关闭或淘汰标签时释放该视图及相关 UI 请求；Diff 另保留有界的运行期缓存，方便重新打开。关闭最后一个标签后返回聊天/原主视图。
- 文件内容与该文件的 Diff 共用一个标签名额，可在标签内切换查看模式；已删除文件可只查看 Diff。显式重新打开已有文件时可更新查看模式，但不改变 FIFO 顺序。
- 外部文件变化通过刷新更新预览；文件被删除、项目被移除后显示不可用状态，不继续把旧缓存当作最新内容。

## 4. Git：Diff、Add、按文件提交与 Rollback

### 展示与操作范围

- 顶部展示项目名称、实际仓库、分支及刷新入口；非仓库、Git 未安装、仓库不可访问分别显示可理解的状态。
- 2026-10-29 补充：非 Git 仓库显示电脑图标、「本地」和 `Local project`，不显示红色警告和提交区域；Git 缺失、权限等实际故障仍显示错误。
- 变更列表分为可折叠的 `Changes` 与 `Unversioned Files` 两组：已跟踪变更（含已加入版本控制的新增文件）归入前者，未跟踪文件归入后者；各组显示文件数，支持整组选择、取消与半选状态。选择不修改 index，不提供暂存/取消暂存按钮。
- 文件行采用紧凑字号与间距，文件名后淡色显示相对项目根目录的父路径，根目录显示 `.`；悬停可查看完整名称与相对路径。折叠状态按项目/仓库在运行期保留。
- 列表左侧复选框只表达「本次提交选择」，选择/取消选择不修改 Git index。
- 项目是仓库子目录时显示实际仓库根目录，并注明列表范围。实施默认值：列表和可选择操作限定在所选项目目录内，不自动把仓库其他目录的文件加入操作范围。
- 同一实际仓库的多个项目视图共用写操作串行控制，操作成功后使相关视图缓存失效。
- 子模块和嵌套仓库识别为独立边界，首版不递归操作其内部改动；不支持的条目明确说明原因，不能被普通文件全选误处理。

### Diff

- 点击条目在只读预览中展示相对于 HEAD 的完整文件改动，与按文件提交的范围一致，而不只显示「工作区对 index」的差异。
- Diff 按项目根目录及相对文件路径缓存，重复打开、切换标签、返回聊天后重开和文件/Diff 模式切换直接复用结果；同一文件的并发查询合并。缓存上限为最近 128 个文件、估算 24 MiB，使用 LRU 淘汰，不写磁盘。
- 启动取得 Git 状态后、状态版本变化后，每个可见项目后台预加载前 24 个变更文件，最多同时读取 2 项；用户点击直接读取或合并已有请求，不排在后台队列后。未变化的轮询不重复预加载，旧版本和已移除项目的排队任务取消。原生 Diff 只读取目标文件的 Git 状态和差异，不为单文件预览重复计算整个仓库的提交校验版本。
- Git 状态版本变化、提交/恢复成功时清理对应项目的 Diff；手动刷新预览只清理当前文件。移除项目释放缓存，失效后迟到的响应不能重新写回；失败结果不缓存，可重试。
- 已有暂存、未暂存以及同文件部分暂存的状态不能让 Diff 漏掉本次拟提交内容。必要时提供简短提示：本次按文件提交包含当前文件全部改动。
- 未跟踪文件展示新增内容，删除文件展示被删除内容，重命名展示原路径和新路径；没有 HEAD 的新仓库按空基线展示新增内容。
- 二进制与超大 Diff 显示状态、大小/限制信息，不伪造文本差异，不把截断内容说成完整预览。
- 提交/撤销前若 HEAD、文件内容或相关 index 状态发生变化，旧预览和选择需要重新校验，不能按旧画面静默处理新内容。

### Add

- 用户可对未跟踪文件执行 Add（界面建议文案「加入提交」），将该文件加入本次待提交选择。
- 此处 Add 是产品层的加入选择，不是立即执行 `git add`；实际必要的 Git 写入发生在提交阶段。取消选择不删除文件，也不改变外部已有暂存。
- 尊重 Git ignore；首版不提供强制加入已忽略文件。未跟踪目录展开为具体文件，不把目录中未展示的内容隐式加入提交。

### 部分提交（按文件）

- 支持选择部分文件，一次提交其当前完整改动，包括选中新增、删除及重命名；不支持选行或选 hunk。
- 底部固定 commit 信息输入框与「提交所选 N 个文件」按钮。信息为空白、无选择或正在提交时禁用按钮；普通 Enter 换行，Ctrl+Enter 可触发可用的提交操作。
- 提交仅创建本地 commit，不推送远端，不修改用户 Git 身份和签名配置，不跳过 hooks。提交成功返回实际 commit 短哈希并刷新状态，随后清空本次选择和已成功提交的信息。
- 未选择文件不能因为已暂存而被夹带进 commit；其工作区内容和暂存意图必须保留。选中文件已有部分暂存时，提交范围仍为已展示的当前完整文件改动，成功后正确协调这些路径的 index，不能留下虚假的反向改动。
- 在实现提交命令之前，以临时仓库验证所选路径提交策略及失败恢复；不能简单采用全仓库 `git add -A` 后 `git commit`。
- 提交前绑定并检查仓库、HEAD、选中路径与预览版本；冲突或 merge/rebase 等未完成操作首版显示原因并禁用提交，不替用户完成这些操作。
- 执行期间禁止同仓库重复写入。外部程序不受应用锁控制，仍需使用 Git 锁和版本检查，不强行删除外部锁文件。
- 失败保留 commit 信息和有效选择，展示原因并刷新真实状态。hooks、签名或超时可能产生实际副作用，应核对 HEAD/index/文件状态，不盲目重试或假定完全无变化。
- 初次提交（没有 HEAD）、中文/空格/特殊字符路径、删除和重命名均需测试；重命名跨项目操作边界时拒绝并说明，不扩大范围。

### Rollback

- 首版含义固定为「将所选已跟踪文件恢复到当前 HEAD」，包含这些文件已有暂存与工作区的未提交更改；不是撤销历史 commit，也不是 reset 分支。
- 操作入口与提交分开。确认展示项目、仓库、目标文件和范围，并明确未提交内容将丢失；只影响确认的文件。
- 未跟踪文件以及 HEAD 中不存在的新增文件不执行 Rollback，不通过 `git clean` 或文件删除模拟恢复；列表解释这类文件没有可恢复版本。
- 首版可以限定为单文件及同项目多文件恢复；重命名按完整操作范围校验，不能只恢复一端而隐式删除另一端。
- 确认后再次校验目标与版本，期间外部内容改变则刷新后重新确认。成功刷新文件树、Diff、预览与 Git 列表；部分失败必须逐项报告实际结果。
- 无 HEAD、冲突、未完成 merge/rebase、子模块等无法满足上述语义的情况禁用并说明，不提供猜测性的恢复。

## 5. 原生接口与状态约束

- 新增独立文件访问与 Git 服务，通过类型明确的 Tauri 命令接入，不通过 pi 或模型执行文件查询和 Git 操作。
- 原生层维护有效项目根目录约束，对传入路径进行规范化、越界和符号链接检查；不能仅依赖前端传来的绝对路径。删除文件/重命名旧路径等不存在的目标使用正确的父目录与 Git 路径校验。
- Git 调用使用系统 Git 和参数数组，路径按字面值处理，提交信息作为输入数据传递；不拼接 shell 命令。Windows 子进程不弹终端窗口。
- 查询放入异步/阻塞工作线程，限制输出量与并发，避免大仓库阻塞 UI。查询可取消，写操作中断后核对实际状态。
- 刷新时机（2026-10-29 更新）：启动时预读最多 5 个可见项目，此后每 5 分钟后台刷新，并在窗口重新获得焦点、用户手动刷新、提交/撤销完成时更新。切换浏览项目直接读取共享缓存，关闭侧栏不停止刷新。
- 应用内 AI 的写入、编辑、命令工具返回及每轮运行结束后，按所属项目合并刷新（750ms）；后台聊天同样生效。Git 版本变化同步更新打开的 Diff。外部编辑由五分钟轮询、窗口焦点或手动刷新感知，不增加文件系统监听。
- 并发查询合并，移除项目清理缓存并忽略迟到结果；写入期间暂停该项目的后台查询，旧查询不覆盖写入后的结果。
- 新能力不修改 pi 配置、供应商凭据或真实会话存储；文件预览不会自动发送内容给模型。
- 检查 `src-tauri/capabilities/` 和命令暴露范围，仅开放所需能力；新增模块与 mock bridge 同步定义返回类型和错误状态。

## 验收矩阵

| 场景 | 必须验证 |
| --- | --- |
| 工具切换 | 顺序正确、颜色有层级、再次点击收起；后台聊天、草稿与会话状态保留 |
| 项目选择 | 默认跟随当前项目；手动选择后不随聊天切换；回到当前项目恢复跟随 |
| 多项目 | 文件/Git 共用下拉；项目失效正确回退；旧请求和写入结果不串项目 |
| 文件树 | 懒加载、空目录、权限失败、大目录限制；链接不越界、不循环 |
| 预览标签 | 全局最多 3 个；A/B/C → 查看 A → 打开 D 后为 B/C/D；重复文件不占位 |
| 预览恢复 | 跨项目同名文件区分；切换项目保留标签；关闭后返回聊天且草稿/阅读位置保留 |
| Diff | HEAD 到当前完整改动与拟提交一致；部分暂存不漏内容；新增/删除/重命名正确 |
| Add 与选择 | 仅改变待提交选择；不写 index、不包含忽略文件或目录中的隐藏选择 |
| 部分提交 | 仅提交选择文件；未选择但已暂存内容不夹带、不丢失；选中文件部分暂存正确处理 |
| 提交失败 | hooks/签名/身份/锁等失败可理解；信息保留；核对真实状态，不自动重复提交 |
| Rollback | 明确确认范围；只恢复目标已跟踪文件到 HEAD；不删除未跟踪文件、不重置分支 |
| 外部变化 | IDE/agent 改文件及外部 index/HEAD 变化后刷新、失效检查与写入目标正确 |
| 仓库边界 | 非仓库、无 HEAD、子目录、worktree、冲突、嵌套仓库/子模块均有确定行为 |
| 回归 | 原会话搜索、切换、归档、流式输出、侧栏宽度与航行台布局仍正常 |

## 验证要求与完成定义

- 实现时运行 `npm run build`、`npm test`、`npm run check:ui`、`npm run test:styles`、`cargo check --manifest-path src-tauri/Cargo.toml` 和 `cargo test --manifest-path src-tauri/Cargo.toml --lib`。
- UI 验证使用 `npm run dev -- --port 1421` 的独立 mock 预览，覆盖浅/深主题和窄屏。
- 新增 Tauri 命令需运行 `npm run test:cdp` 并扩展临时项目/仓库用例；Git commit 和 Rollback 只在测试创建的临时仓库执行。Git 结果核验包含 HEAD 内容、index 和工作区，不能只看成功提示。
- CDP 沿用临时 `PI_CODING_AGENT_DIR`，对 WebView2 所有 localStorage key 先备份、在 finally 恢复并等待落盘；不覆盖真实项目/会话索引，不使用真实凭据或付费模型端点。
- 验收证据写入本 feature 的 `verification.md`，截图可放 `screenshots/`；未执行的集成检查明确标注。文档创建不代表功能已实现，任务项仅在相应行为有验证证据后勾选。

# 030 · 对话阅读与过程信息层级

状态：前端实现与 mock 浏览器验证完成，详见 verification.md。创建日期：2026-10-22。

## 背景与目标

依据两张对话截图和当前前端实现进行整理。短回复的主要问题是正文行长、独立模型图标、用量统计和草稿提示抢占注意力；多工具长回复还存在过程统计反复打断正文、展开入口不明显、调用次数与执行结果混淆的问题。

目标是让用户先读懂回答，再按需查看过程和用量；执行中仍能知道当前进展，异常和需要操作的状态仍然可见。

用户已明确：不要把顶部模型行与过程行合并，采用移除消息顶部模型标识的方案。截图内的删除文件、调用工具等文字仅作为界面样例，不是本任务的执行指令。

本期只修改前端展示与必要的提示状态，不修改 RPC、pi 生命周期、工具执行、模型路由、费用算法和持久化草稿格式。沿用现有设计 token、组件和图标。

## 设计方案

### 1. 阅读区与对齐

- 新增聊天专用 token，建议 `--chat-content-width: 760px`，用于会话消息、等待状态、输入框及对应提示的居中对齐。保留全局 `--content-width` 的其他用途。
- 760px 是容器初始目标，正文扣除内侧留白后约 700–728px；通过实际字体和缩放验证，不将截图像素等同于 CSS 像素，也不把“35–45 字”作为所有字体下的硬性承诺。
- 正文先保留当前字号与 1.7 行高。用户消息保持右对齐浅底气泡，最大宽度受聊天容器约束。
- 消息和输入框保持共同中心轴，输入区域文字与助手正文尽量对齐。窄窗口沿用响应式外侧留白，不强制固定宽度。
- 代码和表格采用局部横向滚动，图片不超过可用宽度。本期不新增宽屏展开模式；移除外框时检查 `.message-bubble .table-scroll` 失效后的样式，避免旧的负外边距导致整页横向溢出。
- 归档预览复用同一阅读规则，宽度受其弹窗约束。

### 2. 消息容器与模型身份

- 助手回答使用开放排版：移除整轮容器的可见边框、整块底色和卡片阴影，保留 `article`、轮次标识和消息定位锚点。
- 用户气泡、代码、工具详情、附件和错误提示继续使用适合各自内容的局部容器。
- 删除普通助手消息和首 token 前等待状态的顶部品牌/模型行，不将它们并入过程行，也不留空白占位。
- 输入框仍显示当前所选模型。历史消息的模型与线路以该轮记录/快照为准，在详情中可追溯；无用量的历史消息也应有实际模型信息入口，不能借用当前选中模型冒充历史身份。
- `processStatus.ts` 的 `modelLabel` 实际来自 `processStepLabel()` 提取的思考片段，并非模型身份。实施时不要根据变量名称误删进度内容；对其显示按下一节的摘要规则处理。
- 保留复制、编辑并重发、继续操作及键盘可达性；重新定位原来依赖卡片边缘的操作条，避免覆盖正文或下一轮内容。

### 3. 过程摘要与展开

保留现有 `turnProcessPresentation()` 的段落边界、稳定分组 ID 和工具结果匹配。助手写出的中间正文、步骤标题、最终答案继续按原顺序显示，不把工具演示文字自动归为可隐藏日志，不增加“只看结果”模式。

| 情况 | 默认展示 | 展开内容 |
| --- | --- | --- |
| 等待首条内容 | 正在思考…，沿用真实等待计时 | 无详情时不显示可展开箭头 |
| 只有思考且已结束 | 查看思考过程 | 原有思考内容；段数和字数不在摘要显示 |
| 单一工具类别 | 读取文件 2 次、编辑文件 1 次等明确调用单位 | 工具名、目标、参数和输出 |
| 多种工具类别 | 最多两个简短动作；更多类别使用“查看 N 次工具调用” | 全部调用按原顺序展示 |
| 工具与思考混合 | 优先展示工具动作，省去重复的思考统计 | 同时保留思考和工具详情 |
| 未知工具 | 使用工具名或“查看 N 次工具调用” | 原始调用与结果 |

- 摘要依据已有工具类型和结果生成，不额外请求模型概括，不把调用过某工具写成已经达成任务目标。
- 活跃步骤优先显示当前动作，如“正在执行命令…”；避免将长思考片段与多个计数并列塞进一行。已有准确等待计时继续使用，不用字数推算耗时，不编造“思考了 8 秒”。
- 有内容可展开的摘要使用常驻小箭头表示展开/收起，整条摘要可点击；思考可保留一个小图标，工具汇总不重复放装饰性星形。
- 复用原生 details/summary 或现有可访问实现，保留 Enter、Space、焦点提示及 aria 状态。错误状态不能被文本省略挤掉。
- 初次显示默认折叠详情；用户主动展开后，流式更新和轮次完成不强制收起、不重置焦点。历史搜索仍可展开并定位命中内容。

### 4. 次数、完成与错误语义

- 工具调用次数和唯一文件数分开。当前已有可靠调用条目，可直接显示“读取文件 2 次”；本期不增加文件去重统计，不能把一次批量编辑等同于一个文件。
- `find`、`grep` 等工具不在新摘要中统称 shell 命令；按实际类别显示动作，多类别过多则退回总调用次数。
- 缺少工具结果显示“等待结果”或结束后的“未收到结果”，不能因为整轮结束就标为成功。
- 失败调用在详情中始终保留。存在未明确解决的失败时，摘要保留失败提示；中断、输出长度上限和继续入口沿用现有语义。
- 仅当数据能可靠关联失败与对应重试，并确认成功结果时，才显示“重试后完成”。当前数据不足时显示“有调用失败，查看详情”，不能依据后续任意成功调用或模型正文中的自述推断错误已解决。
- 本期不引入新的重试关联协议；区分供应商连接重试提示与普通工具执行失败，保留现有重连进度和待确认入口。

### 5. 垂直节奏

- 用现有间距 token 建立三级节奏：同一步骤正文与过程入口约 4–8px，独立正文块或步骤约 12–16px，新一轮约 24–32px。
- 优先减少过程入口周围的重复间距，不同时压缩 Markdown 段落、列表和标题的全部间距。
- 折叠行保留至少现有 compact 控件的操作高度，避免为了密度压缩点击区域。
- 执行过程中保留当前步骤的可见反馈，不为每个已完成动作增加单独的大卡片。结束后依旧只保留紧凑过程入口。
- 回到底部按钮完整位于 transcript 可见范围内、输入框上方，与边缘保持安全间距；不采用容易在窄窗口被裁切的外置定位。
- 上翻阅读时不抢回底部。摘要变短、首 token 到来、等待状态替换和手动展开时均检查滚动锚点与焦点稳定性。

### 6. 用量详情

- 正常完成轮次的页脚默认只显示时间和“用量详情”按钮；不默认展示 token 箭头、缓存闪电、缓存率和多位小数费用。
- 复用现有 Popover，把输入、输出、缓存、思考、总量、费用、费用估算说明和实际模型/线路放在详情中。保留复制精确费用与模型名的能力。
- 没有 usage 但有历史身份信息时显示“消息详情”，说明用量未记录，保留模型来源；无来源信息显示未知，不虚构身份。
- 详情通过点击或键盘开启，Escape 关闭并返回触发按钮；不依赖 hover，不通过展开占位推动正文。
- 不改变一轮多条消息的用量汇总和尾部归属，usage-only 消息不产生额外空白行。未知费用不等于免费。
- 使用现有次要文字色并验证两种主题的对比度，通过减少常驻内容降低噪音，不继续把可操作文字无限调浅。

### 7. 草稿恢复与输入区状态

- 成功提示显示在输入框内部左侧的独立状态位置，文案为“已恢复上次输入”。不覆盖用户文字、附件、模型选择或发送按钮，不作为 placeholder。
- 仅在兼容草稿的文字或可恢复附件实际应用后触发；空记录、读取失败、项目/会话不兼容不得显示成功。
- 每次实际恢复事件最多提示一次：展示 4 秒，用户开始编辑、成功发送或主动清空时提前消失；仅聚焦不关闭。自动保存状态变化不得让提示反复出现。
- 提示采用不影响布局高度的方式出现/消失；在窄窗口验证不与其他控件重叠。使用 polite 状态播报，不逐次保存重复播报。
- 恢复事件与草稿目标绑定。切换会话、组件卸载、目标变化时清理旧计时器，旧提示不得串到新会话；只切回已经在内存中应用的草稿不重复提示恢复。
- 保存失败、读取失败、不兼容及附件缺失为持续状态，不使用成功提示的计时器；在输入区附近左对齐显示，并保留重新添加/移除等现有操作。
- 不改变缺失附件阻止发送、编辑历史消息、取消编辑恢复先前草稿等行为。

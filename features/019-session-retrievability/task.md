# 019 · 会话可检索性与后台状态可见性

状态：已实施并验证，见 [verification.md](verification.md)。创建及修订日期：2026-10-15。依赖 `017-parallel-sessions` 的运行池与 `015-sidebar-archive-polish` 的归档语义；在 020 之后、018 之前实施。
来源：产品评审及源码复核。修订补充未访问历史的加载、后台授权归属与草稿持久化边界；源码行号仅供定位。

## 背景与目标

017 让多个会话可以并行运行之后，侧栏从「导航列表」变成了「任务面板」，但它仍然按单会话时代的假设工作：标题不可辨识、搜索范围过窄、后台会话的状态只有「正在生成」一个圆点。

- 标题派生自首条消息。`src/chat/usePiSessions.tsx:34` 取第一条 user 文本 `.slice(0, 48)`，非 `customTitle` 时每次重算。结果是当前界面里 5 条会话标题都是「你好」、4 条都是「背一下三字经」。
- 搜索只匹配标题与项目名。`src/components/Sidebar.tsx:145-154` 的过滤条件是 `chat.title.toLowerCase().includes(query)` 与项目名，不含任何消息正文。标题既然来自首句，搜索也就只能搜到首句，「找回上周那个结论」这条主链路是断的。
- 后台会话状态不可见。`src/chat/usePiSessions.tsx:76-90` 的 `runningIds` 只由 `pending`/`isStreaming`/`activeRun` 计算；`src/App.tsx:353` 传给 `Sidebar` 的也只有 `runningIds`，`lastError` 与 `routeAuthorization` 留在应用层且只读当前会话。用户在 B 会话干活时，A 会话报「余额不足」或弹出线路授权确认，没有任何提示。
- 同一批会话渲染两遍。`Sidebar.tsx:219-229` 在项目分组内按 `dayLabel` 渲染一次，`Sidebar.tsx:246-251` 的「最近」区又用 `projectHistory.recent` 渲染一次。
- 分组标签语义错误。`Sidebar.tsx:9-18` 把 7 天内一律叫「本周」，第 8 天直接跳到「10 月」，于是出现「今天 / 本周 / 10 月」，而「10 月」桶无法继续下钻。
- 「新聊天」与「主页」是同一个入口。`App.tsx:353` 的 `onHome` 与 `onNewChat` 都指向 `openLauncher`，两者都进 `view === "launcher"`。
- 切换会话静默丢草稿。`src/components/ChatView.tsx:43,46` 的 `draft`、`restoredImages`、`restoredFiles` 都是组件内 `useState`，而 `App.tsx:367` 给 `VoyageWorkspace` 的 `key` 是 `${session.owner.id}:${session.owner.cwd}`，切会话即重挂载。写了一半的长提示词点一下侧栏就没了。

本 feature 的目标是让会话「找得到、看得懂后台在发生什么、切走不丢东西」。

## 行为约定

### 标题

- 保留用户手动改名（`library.renameChat` → `customTitle`）的最高优先级，自动派生逻辑不得覆盖它。
- 第一版采用本地确定性标题：首条 user 正文归一化并压缩空白、截取最多 32 个 Unicode 字符，附模型别名；图片单独输入用「图片聊天」，无正文用「新聊天」。这是显示摘要，不调用模型生成，也不自动写 `set_session_name`。
- 同项目自动标题重复时追加会话创建时间；旧数据没有创建时间时以稳定 chatId 后缀区分。后缀不得使用会随排序变化的序号，也不能把 updatedAt 当创建时间；若新增 createdAt 字段，缺失时兼容读取。别名缺失仍可创建会话，不回退为长原始模型 id。
- 侧栏行内不再把原始模型 id 直接拼在标题后（当前会出现被截断的 `moonshotai/Ki…`）；模型信息用别名，完整线路保留在悬停提示，与主页「最近会话」共用同一份 `routeSnapshot` 口径。

### 搜索

- 搜索必须覆盖消息正文。命中后展示「所在会话 + 命中片段」，点击跳转到该会话并定位到命中消息。
- 明确区分「标题匹配」与「正文匹配」两组结果，避免用户以为只搜到标题。
- 搜索范围是 workspace 中所有未归档会话的 user/assistant 正文文本块，包括重启后尚未访问的历史；第一版不搜索 thinking、toolResult、系统消息或附件二进制。正文中可见的文本附件内容随文本块检索，不引入 OCR 或额外文档解析。
- 已有 runtime 的会话复用其 messages，压缩前未在 messages 中的内容也通过只读历史补齐，按 entryId/消息指纹去重。未访问会话走独立只读历史加载，不为了建立索引创建 SessionRuntime 或启动整池 pi 进程。索引仅存内存，不持久化正文副本；归档/删除时清除缓存和结果。
- 采用受限原生命令按 sessionFile 读取 pi JSONL，读取工作放在阻塞任务中，不复用活动 RPC 的 `switch_session`。第一版支持当前 `get_pi_agent_dir()/sessions` 下已入 workspace 索引的会话；规范化路径并检查普通文件、目录边界、会话 header 与项目 cwd，拒绝越界文件。目录外会话、文件缺失或不支持版本明确显示「部分历史未能检索」，不能当成无匹配；不开放通用任意文件读取能力。
- 历史读取按 pi 文件版本重建当前分支，兼容线性 v1 与树形 v2/v3，不把其他分支消息混进来。压缩前仍在该分支的正文也可检索；读取追加写入中的文件只接受完整 JSON 行，损坏中间行/断链须报告失败，不能静默截短。原生读取前后检查文件版本标识（大小/修改时间等），变化时重试或丢弃该批结果。
- 稳定定位使用 `chatId + sessionFile + entryId + 分支版本`；当前 `parseMessages` 生成的 `history_N` 和实时临时 id 仅用于渲染，不能跨加载作为定位依据。可用时复用 entryId，否则以角色、时间戳、正文指纹和重复序号匹配；不唯一或分支已变时重新加载并提示，禁止滚到一条近似消息冒充命中。
- 点击结果先打开对应会话，命中仍在可见消息中时展开折叠并定位；命中因压缩不在当前上下文时，展开该会话的只读历史视图定位并高亮原文。这个视图不切换 pi 分支，不执行 rewind，不把旧消息注入模型上下文。
- 搜索采用 150 ms 输入防抖，每个查询生成独立版本号，取消后停止调度新批次并忽略已发出请求的旧结果；正在进行的只读调用允许完成，但不得覆盖新查询。归档/删除或历史分支变动也使旧结果失效。
- 历史按需分批加载，并发最多 2，解析历史缓存使用 LRU，最多保留 50 个会话或 20 MiB 可序列化正文（先达者生效）。缓存淘汰后仍可继续扫描，不能把前 50 个会话当完整搜索范围；加载中、部分结果和不可读取历史分别有可见状态。

### 后台状态

- 为每个已访问会话汇总一个状态：`需要确认` > `失败` > `运行中` > `空闲`，优先级顺序固定；未访问会话不捏造运行状态。错误在关闭提示或新运行成功接收后解除，授权在处理/取消/失效后解除，不能长期保留已经处理的角标。
- 侧栏行用状态角标表达，且**不得只依赖颜色**（009 原则）：角标必须带可访问名称，形状或图标本身可区分。
- 只要至少一个后台会话在运行，就显示「另有 N 个会话在运行」，N 排除当前会话。后台只有待确认/失败时仍保留「N 个会话待处理」入口；两者并存分别展示计数，列表按需确认、失败、运行中排序，每条含可访问状态和「去处理」。
- 将线路授权、自动切换与相关错误处理移到每个 SessionRuntime 或等价的按 owner 常驻控制器，App 只负责当前会话展示和用户选择。仅把 `routeAuthorization` 从 App 传回 pool 不足以覆盖切走后的新错误/新授权。
- 所有处理使用 runtime 的 owner/generation 校验，不以是否处于当前导航为前提；用户授权仍只应用到原会话。保留既有扣费账户授权范围，自动切换失败或需要授权时留在该会话，不绕过确认。
- 状态模型预留 `needsConfirmation` 的可扩展来源：本 feature 接入线路授权，018 接入扩展 pending 对话框。019 无需先实现扩展 UI；018 完成后两类确认复用同一角标和去处理入口。

### 结构与草稿

- 移除侧栏内重复的「最近」区，侧栏只保留项目下的会话列表；主页仍提供跨项目最近会话。固定会话与日期分组也必须去重。
- 分组按本地日历日期而非滚动 24 小时计算：「今天 / 昨天 / 周几 + 日期（2～30 天）/ 年月（31 天及以上）」，每组显示实际条数。覆盖月末、跨年、时区和夏令时边界，固定会话不重复计数。
- 「新聊天」与「主页」语义分开：「新聊天」在当前项目直接建立空白草稿并进入聊天，沿用当前模型；「主页」保留模型与项目选择入口。
- 「新聊天」不复用已有非空草稿；只复用同项目、空闲、正文和附件都为空的空白会话，避免把写到一半的草稿当成新聊天。当前模型不可用时仍进入草稿并明确提示选择模型，发送保持禁用。
- 草稿以 chatId 为主键保存在应用侧独立 IndexedDB store，携带项目路径/分支信息、文本及附件元数据。切换会话、回主页和重载后恢复，显示「已恢复草稿」；保存使用短防抖，导航时刷新待写入任务，并用版本号阻止迟到写入覆盖较新内容。
- 附件正文按实际 UTF-8/base64 可序列化字节计量：单附件最多 1 MiB、单草稿附件合计最多 4 MiB、全库持久化附件合计最多 20 MiB。超额附件只保存文件名、类型、大小及「需重新添加」标记；不把缺失内容的附件作为空文件发送。内存仍有原内容时可继续使用，降级提示要说明重载后需要重加。
- 达到全库附件上限时，新保存附件降级为元数据，不静默删除其他草稿的内容。遇到 QuotaExceeded/存储不可用时重试仅保存文本与元数据；仍失败则内存保留并明确提示未持久化，不能显示保存成功或静默截断文本。
- 空白但有草稿的会话必须保留在 workspace 索引，不能被现有 `persistableConversations` 丢弃。发送成功接收后才清草稿，发送失败保留；删除、归档会话或删除项目时清理对应草稿，恢复归档不复活旧草稿。跨 store 清理需阻止待写入任务重新创建被删除记录，并清除孤立记录。
- 草稿绝不写入 pi 会话文件。workspace 保持 v1，新增可选字段必须兼容缺失；旧数据不具备草稿存储时按空草稿读取。
- 为 018 预留编辑草稿：保存目标消息定位、分支版本及编辑前普通草稿；019 实施普通草稿，018 接通编辑恢复。版本不符降级为普通草稿，取消编辑恢复先前草稿，不能盲目重放 rewind。

## 非目标

- 不改归档、恢复、删除的既有语义（015）。
- 不做视觉收敛与仪表盘改造（020）。
- 不升级 workspace 存储版本；新增 createdAt、草稿保留标记等可选字段兼容旧 v1 读取，草稿正文与附件存入独立 IndexedDB。
- 不引入全文搜索引擎依赖。
- 不调用模型生成标题，不实现任意目录历史导入或跨分支全文搜索。
- 新原生命令仅用于受限只读历史，按仓库规则审查命令注册和权限；不增加写入会话文件或任意文件访问能力。

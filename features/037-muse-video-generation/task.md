# 037 · Muse 视频生成接入

状态：已完成。创建日期：2026-11-12。完成日期：2026-11-12。用户已在应用内完成真实图生视频并确认可用；现有实验开关保留。验证见 [verification.md](verification.md)，使用见 [README.md](README.md)。

来源：在现有「生成视频」工作区接入中转站的 `muse-video`，先支持文生视频与单张首帧图生视频。承接 [036 · 创作工作区](../036-generation-workspaces/README.md)，接口证据和本次测试产物说明见 [Muse 视频接入评估](../036-generation-workspaces/muse-video-assessment.md)。本文记录实施任务、验收标准和当前完成情况。

## 目标与首版范围

- 用户在「设置 → 视频生成」配置 API 地址、Key 和视频模型，回到现有视频页填写提示词并提交。
- 首版优先适配 `https://api.aisenyu.com/v1` 与 `muse-video`；保留服务配置结构，先验证一个服务、一条未完成生成任务，不引入自动服务切换。
- 支持文生视频、单张首帧图生视频，以及从图片画廊进入「以此图生成视频」。
- 展示排队、服务端进度、下载和异常；作品自动保存在本机，支持播放、另存为、打开所在文件夹与复用提示词。
- 切换工具、设置和聊天不停止任务；应用重启后，持有远端任务 ID 的记录可以继续查询或下载。
- 多图/视频/音频参考、批量并发、远端取消、模型自动发现、精确报价和聊天 Agent 视频工具留到后续。

## 实现边界

```text
视频工作区 / 视频设置 → TypeScript IPC → Rust 视频任务管理器
                                            ├─ 创建远端任务并保存 task ID
                                            ├─ 查询状态、退避与重启恢复
                                            └─ 下载至本机 → asset 预览 / 导出
```

- 新增独立 `src-tauri/src/video_generation.rs`、`src/workbench/videoGeneration.ts`、`useVideoGeneration.ts` 和 `src/components/VideoGenerationSettings.tsx`；在 `lib.rs` 注册必要的命令和状态。
- 扩展 `useGenerationStudio.ts`、`GenerationWorkspace.tsx`、设置导航和 `App.tsx`，保持 RPC 传输、任务状态及渲染分离。区分图片/视频任务类型，避免把 `ImageJob` 扩成大量可选视频字段。
- 视频请求由 Rust 发出，独立于 pi、聊天供应商和模型家族协议；复用加密、原子写入与 UI 基础组件，不为本期重构通用媒体平台。
- 沿用 `SKIFF_GENERATION_DIR` 作为隔离根目录，新增 `video-config.json`、`video-jobs/<uuid>.json`、`video-inputs/<uuid>.jpg`、`assets/<uuid>.mp4`。保留现有图片配置与资产格式。
- Key 加密保存，读取只返回 configured/keyHint，前端提交只传服务 ID；Key 和参考图 Base64 不进入 localStorage、聊天、pi、日志、截图或测试夹具。
- 原生层校验服务地址、模型能力、任务归属和资产路径；前端不能通过传入任意绝对路径读取文件。检查 `src-tauri/capabilities/`，只开放所需命令和资产预览范围。

## 任务语义与交互约定

### 提交与恢复

- 提交前持久化本地 UUID、服务/端点与模型快照、提示词、请求规格和参考图快照。同一 UUID 的 IPC 重放只返回原任务，不能再次发出 POST。
- 创建成功立即持久化远端任务 ID。网络超时、响应丢失或应用退出发生在接单与落盘之间时，可能无法确认服务端是否已创建；此时标记「提交结果未知」，禁止自动重发和盲目新建替代任务。
- 原生任务阶段至少区分 `submitting / queued / in_progress / downloading / completed / failed`，并明确表示提交未知、查询暂停、下载失败。远端终态与本地网络/存储故障分开记录。
- 有远端 ID 的任务重启后恢复 GET 查询；已生成但未下载的任务恢复同一内容下载。缺少配置或 Key 时提示重新配置，不重新生成；修改服务地址不得把旧任务发到新端点。
- 首版最多一个未确认结束的远端生成任务。暂停查询不释放生成名额；提交未知提供明确的人工核对说明，允许用户核对后显式结束本地跟踪，操作说明服务端可能仍计费，不伪装成远端取消。
- 远端已完成而本地下载失败不继续占用远端生成名额，保留独立下载重试入口；原生层对每个任务去重查询、恢复和下载执行器。

### 查询与下载

- 查询约每 5 秒一次，网络错误与 429 退避并尊重 `Retry-After`；未知远端状态保留原值和任务，不误判成功或自动重新生成。
- 超过等待预算只暂停查询并提供「继续查询」。未收到远端失败证据时，不能用网络超时显示「生成失败」。
- 进度来自服务端，不用计时模拟百分比。生成 100% 后单独显示下载/保存状态，原文件落盘成功后才显示作品已完成。
- 未验证取消接口前，使用「暂停查询」或「停止等待」，说明服务端可能继续生成并计费。
- 下载流式写入 `.part`，限制大小和超时，校验格式后原子改名；失败只重试同一任务的下载。处理缺失文件、磁盘不足与过期结果，不暴露半成品。
- 同源内容接口可携带 Key；跨域重定向/CDN 请求不得转发 Authorization。不把鉴权写进播放器 URL。

### 参数与参考图

- 保留提示词和模型选择；隐藏无对应已验证字段的运动幅度、帧率滑块，不偷偷改写提示词来模拟这些参数。
- 时长改为模型能力列表，初始验证配置为 5 秒；比例初始为 9:16。其他选项经确认后再开放，Rust 同样校验允许值。
- 分辨率按协议确认后的能力配置发送；确认前不承诺 1080p。分别记录请求值与实际宽高、时长、帧率，无法探测的实际字段显示未知。
- 单图输入上传/拖放后预处理成压缩 JPEG，并在原生层校验内容、体积和像素、保存快照、构造 data URL；压缩预算通过实测确定，不把 320 KB 写死成上游限制。
- 导入图和生成图均转换为受控图片字节，不能向服务发送 `blob:`、`asset:` 或本地路径。动画图的首帧处理要明确，原图不被覆盖。
- 参考图与草稿随工具切换保留；提交使用快照，之后替换图片或修改草稿不改变已提交任务。

# Muse 视频生成

在「设置 → 视频生成」添加服务，填写 API Key，默认地址为 `https://api.aisenyu.com/v1`、模型 ID 为 `muse-video`。保存和读取配置不会创建任务。重启原生开发客户端后使用新增命令，仅刷新前端无法更新旧 Rust 进程。

回到「生成视频」，输入提示词后提交。当前开放 5 秒、9:16；请求使用 `resolution: "1080p"`，服务曾返回 720×1280，因此不承诺 1080p。作品详情分别展示请求参数与 MP4 实际宽高、时长、平均帧率。

## 首帧参考图

用户已于 2026-11-12 在 Skiff 中生成首帧参考视频并确认图生视频可用，截图界面显示 720×1280、5.04 秒、23.8fps。真实验收记录见 [verification.md](verification.md)。此前一次纸船任务的“找不到上传控件”作为历史失败保留，具体原因未确认。

当前「启用单图参考（实验）」仍默认关闭；使用时在视频服务编辑器勾选并保存。关闭时可以保留参考图，但须移除它才能提交文生视频；「以此图生成视频」仍可带图跳转并说明启用条件。

上传支持 PNG/JPEG/WebP/GIF，原文件最大 20 MB；生成时取静态画面，最长边不超过 1536 像素，编码 JPEG，压缩后最大 2 MB，透明区域铺白。Rust 再验证内容和尺寸并保存快照，不覆盖原图。这是客户端预算，不表示上游保证接受任何此范围内的图片。

单图以 `image: "data:image/jpeg;base64,..."` 发送，不发送 `mode/fps/motion/size/seconds`。未接入多图、视频/音频参考或人物相似度增强。

## 任务、恢复与计费

- 一个未确认结束的远端任务占用生成名额。暂停后仍保留名额，避免误以为已取消而重复付费。
- 切换页面不停止 Rust 任务；重启后有远端 ID 的活动任务自动恢复查询，已生成的继续下载，均不重发创建请求。
- 「暂停查询」仅停止本地等待，不承诺停止远端生成或计费。
- 查询遇到网络错误/429/5xx 会退避，尊重数字或 HTTP 日期形式的 `Retry-After`。等待约 15 分钟后可暂停并手动继续；网络故障不等于远端生成失败。
- 创建请求只发一次。结果不明时显示「提交结果待核对」，不自动重试；先核对服务记录，再「核对后结束跟踪」。这不取消服务端任务。
- 下载失败只重新下载同一任务，不重新生成。文件用 `.part` 流式保存，最大 256 MB，校验 MP4 后原子落盘。远端已完成但下载失败时可以提交新视频。
- 用量原样保存在任务中，界面展示可识别的计费秒数、视频数和费用；缺少币种时明确说明，`cost: 0` 不表示永久免费。

作品支持播放控制、拖动进度、声音切换、另存为、打开所在文件夹和复用提示词。预览默认静音循环播放，卡片不自动播放。本地导入作品仅保留在本次运行期间，生成作品持久保存。

## 存储与实现

根目录沿用 Tauri 应用数据目录下的 `generation/`，或由 `SKIFF_GENERATION_DIR` 指定：

| 路径 | 内容 |
| --- | --- |
| `video-config.json` | 服务和本机加密 Key |
| `video-jobs/<uuid>.json` | 本地/远端 ID、原服务地址、阶段、时间、用量、请求及实际规格 |
| `video-inputs/<uuid>.jpg` | 提交时的首帧快照 |
| `assets/<uuid>.mp4` | 已校验的生成视频 |

配置和输入目录不授权 asset 预览，只授权资产目录的直接文件。Key 不进入 localStorage、pi 或聊天，读取只返回 configured/keyHint。首版复用 Windows DPAPI；其他平台没有安全存储时拒绝新增密钥，不回退明文。

旧任务绑定原服务 ID 与地址；地址修改或服务删除后，需要恢复原配置和凭据才能继续查询，不把旧任务发往新地址。删除配置保留作品，已运行的任务可以用内存中的凭据完成。

实现位于 `src-tauri/src/video_generation.rs` 及 `media.rs`、`src/workbench/videoGeneration.ts` / `useVideoGeneration.ts`、`src/components/VideoGenerationSettings.tsx` / `VideoGenerationWorkspace.tsx`。请求独立于 pi；实际规格通过有界的 ISO BMFF 元数据解析获得，运行时无需 FFmpeg。

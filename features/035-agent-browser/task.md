# 035 · AI 浏览器与实时可视化

状态：待实现。创建日期：2026-11-09。

来源：让 Skiff 的 AI 使用 agent-browser 操作浏览器，用户能够实时观看，并在需要时接管操作。本文定义首版范围、实施顺序和验收要求；所有任务尚未开始。

## 目标与首版范围

在聊天中直接提出浏览任务，AI 可以打开网页、读取页面、点击、填写和滚动；Skiff 展示同一浏览器的实时画面及操作记录。用户可以接管完成登录等步骤，再交还 AI 继续。

- 使用独立的 Chrome 浏览器进程，由 agent-browser 驱动；Skiff 内显示它的实时画面。页面内容不加载进拥有 Tauri IPC 权限的应用页面。
- 一个聊天绑定一个浏览器会话，按需启动；先打通一个聊天的完整链路，再完成两个聊天并行时的隔离和切换。
- 首版每个会话使用一个受控页面。多标签管理、复用用户日常 Chrome、跨聊天共享登录、云浏览器、录屏回放、完整 DevTools 后续再做。
- 提供实时观看、网址与连接状态、接管、交还 AI、停止任务、关闭浏览器及失败重试。
- 首个浏览器任务自动展开面板；用户手动收起后，本轮后续操作不反复抢占布局。聊天、草稿及后台任务继续沿用现有会话机制。
- 优先支持当前 Windows 桌面环境；其他平台需要分别验证，不能仅因上游提供二进制就标记支持。

## 已知基础与待验证项

Skiff 已有 pi 扩展注册工具、Rust 子进程管理和聊天运行池，可复用相应边界。agent-browser 上游文档提供命名会话、结构化输出、实时画面流和输入事件；Dashboard 可用于开发时对照，但产品界面使用 Skiff 自身组件。

上游主分支文档不等于本机已安装版本的能力。开发前必须固定并记录 CLI 版本，实测命令、事件格式、Windows 启停和正式包连接方式。

## 实现边界

```text
pi 浏览器工具扩展 ── 操作请求 ──> Rust 浏览器服务 ──> agent-browser ──> Chrome
                                      ↑                    │
React 浏览器面板 ── 接管 / 输入 / 关闭 ──┘ <── 状态与实时画面 ──┘
```

- Rust 浏览器服务统一维护聊天归属、运行实例、控制权和命令串行队列。AI 与人工输入必须经过同一个控制权边界，不能只在前端禁用按钮。
- pi 扩展仅负责工具参数、请求及结果转换；不让模型选择内部会话名、端口或浏览器 profile。
- 先验证扩展到 Rust 的通信方式，建议使用仅本机可访问、具有实例鉴权的桥接接口。启动信息通过受控运行时配置传入，不通过模型上下文暴露。
- React 负责画面渲染、交互和布局；画面数据不进入聊天消息 reducer，也不逐帧写 localStorage 或会话历史。
- 正式包的 Tauri 来源可能不被上游流服务接受。优先实测直连；如不支持，增加本机代理或原生转发，不通过全局放宽来源规则解决。
- 浏览器服务按聊天稳定 ID 绑定资源，另用运行实例 ID / generation 拒绝重连、关闭后的迟到事件。不能仅按项目路径或当前选中聊天路由。

## 用户交互与生命周期约定

### 浏览器面板

- 桌面聊天旁展示可调宽的浏览器面板，顶部保留网址、状态及控制入口。浏览器展开时优先折叠航行台，避免两个右侧面板挤压聊天。
- 窄窗口使用可返回聊天的独立视图；收起、返回、切换聊天均不等于关闭浏览器或停止任务。
- 初始状态显示启动引导；区分依赖缺失、启动中、连接中、AI 操作中、人工接管、已断开和已关闭。
- 画面缩放保持比例，鼠标坐标换算扣除留白；支持滚动、键盘和中文输入。观看模式不向页面发送输入。
- 流断开时明确标记画面已失效，禁用画面输入；重新连接后用当前状态覆盖，不回放积压帧或旧输入。

### 控制权与停止

- 点击「接管」后禁止新的 AI 浏览器操作，并暂停浏览任务继续推进。若 pi 不支持可靠暂停，首版使用中断当前轮次的方式实现，并明确展示状态。
- 已经发出的点击不能声称已撤销；等待在途操作结束或取消得到确认后，才显示「已接管」并开放人工输入。
- 接管期间浏览器工具返回明确的人工控制状态，不允许模型绕过工具通过另一个执行入口继续控制同一会话。
- 点击「交还 AI」后停止接收人工输入并失效旧队列；重新获取页面 snapshot，再恢复或发起续跑，不能复用接管前的元素引用。
- 聊天「停止」同时取消浏览器排队操作和当前工具等待，保留网页供查看；进行中的导航等操作是否实际取消必须以底层结果为准，必要时停止页面加载或重建浏览器连接后再允许新操作。
- 「关闭浏览器」释放该聊天的浏览器、daemon、连接和队列；重新打开视为新运行实例。关闭面板只释放观看订阅。

### 保留与清理

- AI 本轮完成后保留页面；切换聊天不关闭后台浏览器，返回时显示对应会话当前画面。
- 首版浏览器 profile 按聊天隔离，保存在 Skiff 专用目录；同一聊天显式重开时可恢复登录状态，不承诺恢复原页面运行状态。
- 归档聊天及应用正常退出关闭运行资源，保留 profile；恢复归档不自动启动。删除聊天清理其专用 profile，不碰其他聊天及用户日常浏览器数据。
- 处理 daemon 空闲退出和应用异常退出后的残留状态；重启只核对、回收或重连 Skiff 自己创建的资源，不按进程名批量结束 Chrome。

## 执行任务

### A. 技术验证与版本基线（P0，后续阶段的前置）

- [ ] A1. 固定 agent-browser 版本，记录 Windows 安装、可执行文件解析、Chrome 下载位置和最小启动要求。
- [ ] A2. 用隔离 profile 和本地测试站点验证 open → snapshot → click / fill → snapshot，以及 JSON 输出和错误格式。
- [ ] A3. 验证命名会话、随机端口发现、实时帧、网址变化、鼠标/键盘事件、daemon 空闲退出和显式关闭。
- [ ] A4. 在 Vite 预览和 Tauri 正式构建中分别验证画面流连接；确定直连或代理方案，记录实际来源限制。
- [ ] A5. 验证 pi 扩展到浏览器服务的通信、工具中断及在途命令取消能力；明确接管屏障和任务暂停实现。
- [ ] A6. 在本 feature 新增 `DESIGN.md`，记录以上证据、版本、接口及失败路径；据此修订后续任务，不把未验证能力写成已完成。

验收：Windows 上使用真实 agent-browser 打开本地页面，Skiff 桌面能显示实时变化并完成一次人工点击，资源可正常关闭。

### B. 原生浏览器服务与依赖管理（P0，依赖 A）

- [ ] B1. 新增独立浏览器服务模块和类型化 Tauri 接口，覆盖依赖状态、启动、查询、接管、交还及关闭。
- [ ] B2. 支持配置 CLI 路径及 PATH 探测，展示版本和浏览器依赖状态。首版提供明确安装指引与重新检测，不在聊天启动时静默下载。
- [ ] B3. 实现聊天 ID → 专用 session / profile / 运行实例映射，以及启动去重、命令串行、超时和输出上限。
- [ ] B4. 用参数数组执行受支持命令；Windows 后台子进程不弹终端。界面只展示可理解的错误，不泄露运行时凭据。
- [ ] B5. 实现扩展桥接和必要的画面/输入转发；接口验证资源归属和运行实例，检查 `src-tauri/capabilities/` 暴露范围。
- [ ] B6. 完成停止、关闭、崩溃、空闲退出和正常应用退出清理；依赖缺失或浏览器故障不阻断普通聊天。

验收：无需模型即可通过服务接口启动、操作和关闭两个独立浏览器；一个失败不影响另一个及普通 pi 会话。

### C. pi 浏览器工具（P0，依赖 B）

- [ ] C1. 新增 `src-tauri/src/pi_extensions/agent_browser.js`，通过 Skiff 的扩展加载路径接入，尊重 `PI_CODING_AGENT_DIR`，保留已有扩展和供应商配置。
- [ ] C2. 定义结构化浏览器工具，首批操作包含打开、页面 snapshot、点击、填写、按键、滚动、等待和截图；按固定版本能力实现，不直接暴露任意 shell 字符串。
- [ ] C3. 注入简洁操作说明：读取 snapshot、使用当前元素引用、操作后核对、页面变化后重新定位。工具 schema 和说明与 CLI 版本对应。
- [ ] C4. 统一返回文本、截图及操作元数据，包含操作 ID、目标、耗时和实际终态；区分页面错误、超时、取消和人工接管。
- [ ] C5. 把 pi 的 abort 传到底层服务；接管或关闭后拒绝迟到请求，避免执行自动重试导致重复提交或点击。
- [ ] C6. 为浏览器能力增加设置开关；禁用时不向模型注册可用浏览器工具，已有聊天重连后的状态一致。

验收：真实 pi 在本地测试站点完成「打开页面 → 填写字段 → 点击 → 核对结果」，操作命中所属聊天，取消可传到服务。

### D. 实时画面与聊天布局（P0，依赖 B；可使用 mock 先开发）

- [ ] D4. 限制帧率和缓冲，仅渲染最新帧；隐藏面板或后台聊天暂停观看订阅，释放图像资源和监听，不停止后台任务。

### E. 人工接管与操作记录（P0，依赖 C、D）

- [ ] E3. 接管时暂停/中断当前浏览任务；交还后获取新 snapshot，并通过明确的续跑动作继续任务，记录是否创建了新一轮。

## 最终验收矩阵

| 场景 | 必须满足 |
| --- | --- |
| 首次使用 | 依赖缺失有可执行指引；检测失败不影响普通聊天 |
| AI 浏览 | 真实 pi 完成打开、读取、交互和结果核对；用户实时看到同一页面 |
| 动态页面 | 页面变化后重新获取引用；错误与超时可理解，不伪报成功 |
| 人工接管 | 服务确认控制权后才开放输入，接管期间无 AI 排队操作落地 |
| 交还继续 | AI 读取最新页面状态；旧输入及旧元素引用不复用 |
| 停止与关闭 | 停止保留页面、关闭面板保留任务、关闭浏览器释放资源 |
| 多聊天 | 两聊天页面、cookie、画面、输入与终态独立；迟到事件不串线 |
| 异常恢复 | 浏览器退出、流断开、pi 重连及快速重开可恢复或明确报错 |
| 布局与主题 | 浅深主题、600×400 窄窗、键盘和中文输入可用，无横向溢出 |
| 正式包 | 实际 Tauri 发布构建可连接画面及完成接管，不只通过 Vite 预览 |
| 数据保留 | profile 按聊天隔离；删除范围准确；不修改真实 pi 凭据及 workspace 索引 |

## 里程碑与建议顺序

1. **M1 · 可行性闭环**：完成 A；真实浏览器画面在桌面内可见，人工输入可到达页面，确定正式包连接方案。
2. **M2 · 单聊天闭环**：完成 B、C、D 的基础链路；真实 pi 浏览本地页面，用户能实时观看和停止。
3. **M3 · 日常使用闭环**：完成 E、F；接管、交还、多聊天隔离和生命周期完整。
4. **M4 · 交付**：完成 G 的相关检查与证据，更新安装说明和验证记录。

先验证 M1 再展开其余实现。前期讨论的 1–2 天演示、4–7 个开发日可用版仅作粗估；固定版本、正式包画面转发和人工接管屏障实测后重新评估。
